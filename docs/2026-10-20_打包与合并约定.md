# 打包与合并约定（给日常协作使用）

- 日期：2026 年 10 月 20 日
- 适用：LumeBox 的日常开发、交付与测试包

## 三条规则

1. **没有明确说“出包 / 打包 IPA”，就不出包。**
   - CI 的 iOS workflow 已改成**只能手动触发**；合并代码、push main 都不会自动构建。
   - 需要包时，直接跟 AI 说“帮我打一个测试包”；AI 会触发 CI，然后给出：版本号、GitHub Actions 链接、`ipa/` 下的文件路径、SHA256。
   - 自己也可以在 GitHub → Actions → “Build unsigned IPA (iOS)” → Run workflow 手动触发。

2. **每次工作结束，代码合并回 main。**
   - AI 收工前会：提交改动 → 跑静态检查/测试 → 合并到 main → push。
   - 合并和 push 都**不会**产生 IPA，所以可以放心合并。
   - 没做完、还不稳定的实验性改动留在 `feature/xxx` 分支并 push，不合并 main。

3. **每个测试包都要能对应到代码和验收记录。**
   - 每次出包更新 `docs/2026-10-19_前期交流功能进度与待办.md` 的 5.7 节；
   - `ipa/` 下保留 `*.ipa.sha256`、`*.ipa.json` 和 `安装说明-<版本>.md`；
   - 真机反馈要带上：机型、iOS 版本、场景、选择的渲染方式（如果和液态玻璃相关）。

## 出包流程（AI 侧）

1. 确认代码在 `main`（或需要的 feature 分支）且测试通过；
2. `gh workflow run build-ios.yml --ref <分支>` 手动触发；
3. 等待 CI 成功，下载 artifact（并行下载脚本在 `build/download_ipa_parallel.py`）；
4. 校验并生成 `ipa/` 记录，更新文档；
5. 告诉用户：版本、链接、文件路径、SHA256、这次改了什么、需要重点看什么。

## 回退

- 代码回退用 Git：`main` 每次合并都有提交记录，可回退到上一个版本；
- 包回退：旧 IPA 和校验文件都在 `ipa/`，不会因为出新包被覆盖；
- 如果新包安装失败，先确认是签名/描述文件问题，再考虑代码问题。
