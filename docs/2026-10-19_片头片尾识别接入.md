# 片头片尾识别：接入与验收

本次能力接入独立的「参考播放器」。应用默认仍选择原播放器；原播放器页面、手动跳过规则和设置键不迁移、不覆盖。参考播放器可从「设置 → 阅读与播放 → 播放器方案」选择，识别配置位于参考播放器的「播放设置 → 片头片尾自动识别与跳过」。

## 使用

App 内可从「参考播放器 → 播放设置 → 参考播放器使用说明」，或识别设置右上角问号查看完整指南。17 个方法开关下均提供用途、条件和降级说明。

1. 打开一集视频，等待总时长可用。轻量级查询不阻塞起播。
2. 在「片头／片尾」入口绑定作品 TMDB／IMDb ID、季号。源条目的当前章节序号作为集号；电影单独勾选。没有 ID 时继续本地方案，不猜一个相似作品来跳转。
3. 保持默认优先级，或拖拽调整。所有 17 个识别子方案分别开关。
4. 要测试重计算方案，暂停播放并保持应用在前台；默认还要求 Wi-Fi。用「重试空闲预扫描」重新运行。在日志中确认实际命中的来源和置信度。
5. 识别到片段后显示可取消的倒计时。关闭自动跳过后只保留手动按钮；取消本段后本集不再反复提示。
6. 没有可靠结果时，记录 OP 起点／终点、ED 起点／终点并保存。四点支持毫秒，按集保存；同季复用可独立关闭，时长不符的版本不会套用。

## 方案与实际实现

| 方案 | 位置／实现 | 适用边界 |
| --- | --- | --- |
| TheIntroDB | `community_sources.dart`；当前 v4 `/media`，TMDB 身份，毫秒时间 | 需要真实作品 ID；404、429、版本时长不符继续降级 |
| IntroDB | 同文件；`/segments`，IMDb 身份 | 匿名读取；不代用户提交数据 |
| Chapter | MPV 只读 `chapter-list`；iOS AVAsset 章节组 | 由视频容器提供实际时间 |
| MKV 标签 | 有界 EBML SeekHead → Chapters／Tags，含嵌套章节、章节 UID 标签与显式 OP_START／END 时间标签；MPV 元数据 | 网络源需要有效的 Range；不整片下载，截断标签不参与识别 |
| 内嵌字幕 | iOS AVAssetReader 读取头尾有限字幕样本 | AVFoundation 不支持的容器／字幕编码记录失败，继续降级 |
| 文件名 | OP／Opening／ED／Credits／Prev 等关键词与显式时间范围 | 单独一个 OP 词不能凭空确定起止，不自动跳整部正片 |
| 黑屏／淡入淡出 | 32×32 灰度亮度与相邻变化 | 单独黑屏不足以跳转 |
| 静默 | 有界 16 kHz 单声道 PCM RMS | 与其他边界信号组合 |
| 场景切换频率 | 相邻图像差异与窗口内切换计数 | 稀疏采样启发式，需实际样片校准 |
| 滚动演职员 OCR | iOS Vision；Android 本地 ML Kit；文字行匹配与上移 | 只对片尾区域应用，普通静止字幕不作为滚动证据 |
| pHash／dHash | Dart 后台 isolate，低频 DCT／图像梯度 | 排除平坦黑帧，要求至少 5 个一致时间偏移样本 |
| MFCC | 25 ms Hann、FFT、26 Mel、12 个非能量系数 | 只对有声样本比对，不把静默当作锚点 |
| 联合指纹 | 图像与音频同时满足时间序列匹配 | 同剧同季的可靠标注作为模板；各单流方法可关闭 |
| 视频 AI | Apple MobileCLIP-S0 Core ML，8 个文本锚点，连续帧分类 | 是零样本语义方案，不是专门训练好的 OP／ED 模型；分数尚未校准 |
| 音频 AI | YAMNet，单线程 TFLite 后台 isolate | Speech／Music 实际模型分数；不是“音乐就等于片头” |
| 手动兜底 | `intro_episode_sheet.dart` 与独立 SQLite | OP／ED 各两个时间点，支持同季复用与本集覆盖 |

默认顺序是社区库 → 手动历史 → 内置元数据 → 指纹 → 启发式 → AI。元数据单独列出，避免被遗漏。某层可靠命中后停止后续识别；可靠社区／手动／章节时间可在空闲时学习指纹，这一步不再运行其他识别器。重叠的指纹建议全部记日志，实际只执行一个范围。

## 资源和持久化

- 播放跳转仍走 `AbstractPlayer.seek`，适用于 MPV、AVPlayer、MDK。检测不拖动正在播放的实例。
- iOS 使用独立 AVAsset；Android 使用独立 MediaMetadataRetriever／MediaExtractor／MediaCodec。iOS 不支持的媒体编码会降级，不承诺任何解码器都能预扫描所有容器。
- 默认只在前台空闲运行重计算；播放恢复或应用进入后台时取消，回到空闲后重试。没有宣称 iOS 进入挂起状态后还能持续执行。
- 单任务、串行采样、180 ms 采样间歇、250 ms AI 间歇、有限头尾窗口。可调整每轮预算、间隔、采样数、最低置信度。低电量、严重温控、可用内存不足会暂缓。
- 计算预算是调度预算，原生单次 I/O／首次 Core ML 编译不能保证在毫秒级抢占；没有虚构固定 CPU 百分比上限。
- 数据库为应用支持目录的 `reference_intro.sqlite`。手动与机器结果分开；机器缓存受社区身份 ID、配置、版本时长和有效期约束。指纹最多保留 300 集的模板，日志最多 2000 条。
- 社区请求只发送作品 ID、季集号和时长，不发送视频地址。日志省略媒体 URL 和凭据，可以本机导出 JSON。

## 模型与替换契约

`assets/models/intro/` 中已放入实际模型、文本锚点、校验值及许可文件。MobileCLIP 权重采用 Apple ASCL，软件采用 MIT；YAMNet 采用 Apache-2.0。模型与复现脚本来源为 [Apple MobileCLIP](https://github.com/apple-aiml-research/ml-mobileclip)、[Apple Core ML 权重](https://huggingface.co/apple/coreml-mobileclip)、[Google YAMNet](https://github.com/tensorflow/models/tree/master/research/audioset/yamnet)。

运行 `python tool/prepare_intro_models.py` 可重新获取固定版本并校验 SHA-256。视频模型 ZIP 约 95 MiB，YAMNet 约 15 MiB；首次在 iOS 解压和编译还需要额外本地空间。仅音频方案不解压视频模型。

可在设置中替换：

- 视频：ZIP 内放 `mobileclip_s0_image.mlpackage`／`mobileclip_s0_text.mlpackage` 模型对，或 `segment_classifier.mlpackage`／`.mlmodel`。专用分类器需输出 `recap`、`opening`、`main`、`ending` 四个类别，使用标准 Core ML 图像分类接口。
- 音频：YAMNet 兼容 TFLite，输入为 15600 个 float32、16 kHz 单声道 PCM；首个输出为 521 个 AudioSet 类别。Speech 为索引 0，Music 为 132。
- ZIP 路径、解压大小、模型输入／输出契约都校验；切换后下一次空闲任务生效。可恢复内置模型。

## 验收记录与未验收边界

已完成 136 项 Flutter 侧相关测试（其中识别流程 28 项），覆盖原播放器设置／手势／启动降级、页面路由与新旧设置隔离；静态分析也执行到整个 `lib`。Android 原生取帧／OCR／YAMNet 已真正推理：灰度 1024 像素、PCM 15599 个样本、音频 RMS 约 0.0878，并返回 Speech／Music 分数。测试媒体为本地生成的原创测试图与音调，含 OP、正片、ED 章节，不能用其推断影视片段的分类准确率。

出包前全量复核：2045 项通过、47 项条件跳过、0 项失败（`build/2026-10-19-full-test-final.log`）。修复方案初始化的异步等待后，原视频进度／来源首页 39 项通过；全 `lib` 静态分析无问题。跳过项保留原测试条件，没有通过禁用失败测试获得此结果。

Android API 36 模拟器的 MPV GL 输出复现了上游 [EGL 黑屏问题](https://github.com/media-kit/media-kit/issues/1343)。独立开发入口 `tool/android_player_preview.dart` 使用直连 Surface 后，冷启动已实际显示视频与控制层（`build/player-reference/android-direct-surface-cold.png`），章节倒计时跳过也已验证。该路径强制 MediaCodec，不用于验证软件解码、GL 特效或 MPV 截图。正式入口和 iPhone 的渲染配置不启用该调试参数。MPV 原生实例活跃时应退出应用冷启动，避免模拟器热重启遗留 native 回调。

启动本地预览：

```powershell
python tool/player_preview_server.py
# 另一个终端，模拟器启动后：
adb -s emulator-5580 reverse tcp:8765 tcp:8765
flutter run -d emulator-5580 -t tool/android_player_preview.dart
```

最终仍须在 Mac 编译并在自签 IPA／iPhone 上验证：Core ML 首次编译与四类分数、Vision OCR、各容器字幕与音轨、MPV／AVPlayer／MDK 的实际跳转、温控和耗电、取消与安全区触控。当前 Windows 工作站不能证明这些 iOS 真机项目已通过。

此前“复刻播放器所有设置”的其他部分不应与本次识别混为已完成：参考播放器的评论服务、DLNA、AirPlay 路由入口仍未接入，控件会明确提示。原播放器的相应功能保留。

社区接口依据：[TheIntroDB 当前 API 文档](https://theintrodb.github.io/theintrodb-npm/getting-started.html)、[IntroDB API 文档](https://introdb.app/docs/api)。
