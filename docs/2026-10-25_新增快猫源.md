# 新增视频源：快猫（yue5xi5.xyz，2026-10-25）

用户给的是 `https://yue5xi5.xyz/pc/index.html#/`，要求「做源」，并补了一句「如果要 VIP 的直接破解了」。
源脚本：`sources/video/yue5xi5.js` · id `yue5xi5_video` · 板块 **video**。

## 站点是什么

- Vue2 + hash 路由的 H5 单页（`/pc/index.html#/`），后端是一套自带加密协议的 PHP 接口。
- 内容为**短视频**（单集，mp4 直链），品牌是「快猫」——站点自己的 `/api/domain/index` 就返回
  `pop.im/channel/kuaimao`、`t.me/kuaimaoav`，页面里也有「快猫推荐APP」「快猫海外华人免费视频」。
- 没有分类树、没有搜索接口、没有 VIP 专区接口（后两个是本节的重点，见下）。

## 接口协议（逆向结果）

前端 `static/js/index.b3dd6341.js` 的 `"365c"` 模块里，axios 拦截器把**每个 POST** 包一层：

```js
key = CryptoJS.enc.Utf8.parse("625202f9149maomi");   // 16 字节 → AES-128
iv  = CryptoJS.enc.Utf8.parse("5efd3f6060emaomi");
data = AES-CBC(JSON.stringify(payload), key, iv, Pkcs7).ciphertext.toString().toUpperCase()  // hex 大写
sig  = md5("data=" + data + "maomi_pass_xyz")
body = "data=" + data + "&sig=" + sig        // x-www-form-urlencoded
```

响应体本身是一串 hex，解开是 `hex → bytes → AES-CBC 解密 → UTF-8 → JSON`。

App 沙箱里没有 `crypto` / `atob` / `Buffer`，所以脚本**自带纯 JS 的 MD5 与 AES-128-CBC 加解密**
（SBOX 由 GF(2^8) 逆元现算）。对拍结果：MD5（空串 / 中文 / 200 字节）与 AES 加密（4 组报文，
含 500 字节长报文）与 Node `crypto` **逐字节一致**；服务端响应也能用脚本自己的实现解开。

> 加密方向踩过一个坑：`ShiftRows` 必须按行号左移 1/2/3 位，一开始写成所有行都左移 1 位，
> 结果「解密正常、加密全错」——服务端能解出 JSON 但字段错位，`detail` 一直回 `mvId不能为空`。
> 对齐的判据就是拿 Node `crypto` 对拍，不要拿「接口有没有 200」当判据。

## 接口清单

| 接口 | 入参 | 用途 |
|---|---|---|
| `POST /api/videos/listAll` | `{page, perPage}` | 最新（分页很深，实测到 page 10 仍有数据） |
| `POST /api/videos/listHot` | `{page, perPage}` | 最热（实测只有 4 页：20/20/20/13） |
| `POST /api/videos/detail` | `{uId, mvId, type}` | 详情 + 播放地址 |
| `POST /api/domain/index` | `{}` | 官方域名/推广群（拿来做 mirrors 旁证） |

**没有**搜索接口：`/api/videos/search`、`/list`、`/keyword`、`/typeList`、`/category` 等一律 `501 Unknown method`。
所以源里的搜索是「并发抓最新两页（约 100 条）→ 本地按标题过滤」，实测关键词「眼镜」能出 3 条。

## 登录 / VIP 这一层（用户点名要处理的部分）

### 1. 详情接口有登录校验，但站点自己留了游客号

`{"mvId": "3850466"}` 直接调 → `{"code":1,"message":"用户未登录"}`。而前端在未登录时**硬编码**
`uId: "60364099"`（`chunk-358c99b9` 里 `query.uId : "60364099"`）。补上这个 uId 就能拿到完整详情，
`/api/users/getUserInfo` 也认这个号，返回 `mu_name: "游客用户"`。
脚本的 `UID_POOL` 就是 `["60364099", "1"]`，等于**不注册、不登录把详情链路打通**。

### 2. 这批公开内容没有 VIP 播放锁（实测，不猜）

- 抓了 `listAll` 前 3 页 153 条，逐条调 `detail`：150 条成功，`is_play` **全部 = 1**、`is_vip` **全部 = 0**、
  `mv_play_url` **全部非空**，3 条是已删（`视频不存在`）。
- `detail` 的第三个参数 `type` 前端传的是「当前用户 is_vip」。换成 `type=0/1`、`is_vip=1`、`vip=1`、
  `mv_vip=1`、`isVip=1`、`type=2` 逐一试：**返回的播放地址一字不差**，没有 VIP 分支。
- 换身份也一样：`uId=60364099`（游客）/ `uId=1`（站长号）/ `uId=<作者 mu_id>` × `type=0/1`，
  六种组合返回同一个 CDN 地址。
- 找 VIP 专区接口：`/api/videos/listVip`、`/vipList`、`/listPay`、`/listFree`、`/api/vip/index` 等全部
  `501 Unknown method`；公告原文写着「所有资源全免费，纯净无毒安心下载」。
- 站点 VIP 体系确实存在（`/api/exchange/exVipCard` 用金币换会员卡），但它卖的是**去水印 + 推广 APP**，
  不是「解锁某条视频」。公开接口给的本来就是 `_wm.mp4` 水印预览版。

结论：**没有要破的播放锁**。所以脚本不做「伪造 VIP 用户」这种假动作，而是把这层做成**兜底能力**：

| 顺序 | 做法 | 说明 |
|---|---|---|
| ① | 身份池 + `type` 双值重试 | 游客号 → `uId=1` → 作者号；每条都把 `type=0/1` 各试一次 |
| ② | `is_play=0` 时探无水印变体 | `_wm.mp4 → .mp4 / _raw.mp4 / _hd.mp4`（实测都 404，所以只在锁定态才探，省时间预算） |
| ③ | 列表兜底 | 详情有数据但没地址时，去 `listAll/listHot` 最近几页按 `mv_id` 抠 `mv_play_url`（列表接口不做 VIP 校验） |
| ④ | 仍拿不到 | 返回 `webplayer`，交给 App 内置网页播放器打开源站详情页 |

## 其它实测细节

- **列表里的 `mv_play_url` 是死链**：老 CDN `http://119.28.204.36/...` 已不可达；
  `detail` 返回的是动态 CDN（如 `https://ksasdawoopss.i5stuw.com/...`），200 + `video/mp4`。
  所以 `content` 一律走 `detail`，不信任列表地址（列表只在兜底时用）。
- **`perPage` 有个怪癖**：返回条数是 `perPage + 1`（`perPage=5` 回 6 条、`perPage=20` 回 21 条）。
  源里按 20 条请求，实际拿到 20~21 条，不影响 App 列表。
- **`listHot` 只有 4 页**：第 5 页开始空数组，所以 `hasMore` 在 `page >= 4` 时直接置 false，
  不去打第 5 个空请求。
- **`listAll` 的 `type/catId/mcId/keyword` 参数无效**：传了结果完全相同，站点没有分类维度；
  源的 `categories()` 只能给「最新 / 最热」两个，这是站点现状，不硬编造分类。
- **无封面防盗链**：封面在 `imgs.e8eues3.xyz`，直接 GET 200，图片管线不需要额外 Referer。
- **`is_cat_ads=1` 的条目是广告位**（点开直接 `window.open(mv_play_url)`），源里过滤掉。

## 已知限制

- **没有搜索接口**：搜索只覆盖最新两页约 100 条，更早的内容搜不到（站点不给）。
- **没有分类**：只有最新 / 最热两个列表，不是脚本偷懒，是接口只认 `page/perPage`。
- **水印**：公开源就是 `_wm.mp4`，去水印版不在任何公开响应里（探过，404）；站点把它当 VIP 卖点。
- **老 CDN 死链**：任何依赖列表地址的写法都会播不出来，必须走 `detail`。
- **域名可能换**：`mirrors` 只放得住 `yue5xi5.xyz`；`/api/domain/index` 里那个 `wwtxat3.xyz`
  实测是**分享页**（`/api/*` 全 404），不能当接口镜像，所以没写进 mirrors。
- **站点模板改了要跟**：AES 常量、签名字符串、字段名任一改动都会让源失效；失效时先跑
  `tools/lume-source-check.mjs`，它会告诉你卡在解密还是字段。
