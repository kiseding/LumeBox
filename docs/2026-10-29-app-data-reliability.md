# 2026-10-29 App 数据与可靠性修复

本次修复统一普通源作品的存储身份，补齐迁移到新设备时需要的用户数据，并将分析和回归测试接入 IPA 构建前置检查。

## 升级与恢复

- 阅读库升级为 v5。收藏和最近进度以 `source_id + item_id` 为联合主键，逐集断点额外包含 `chapter_id`；板块仍由独立数据库隔离。传给网站脚本的原始作品 ID 保持原样。
- 迁移在 SQLite 事务内进行，迁移前保留 `reading.db.before-identity-v5`。旧作品归属从原书架元数据补齐；无法确认归属的孤立进度保留为空归属，不猜测另一源的身份。
- 界面查询、删除、多选、收藏分组、漫画书签、Bangumi 绑定及片头片尾标记使用带源身份的键。旧的作品偏好仅在归属唯一时迁移。
- iCloud 文档升级为 v2，能够读取 v1；新键包含源身份，包含逐集断点。旧云端快照最多只能恢复它原先保存的最近一集，不能重建从未上传的其他集数。旧版 App 无法读取 v2，同步设备应一起升级。
- 配置备份升级为 v2，仍能导入旧 v1。恢复前校验订阅、阅读行身份、字段类型和猫源包校验值；首次写入前在 `configuration_backups/before-restore-时间戳.json` 保存当前设备快照。
- 恢复采用合并并覆盖同身份条目的方式。恢复后重新启动 App，以重新载入全部文件配置；猫源恢复后需要手动选择站点。

## 备份范围

| 数据 | 本次处理 | 验证方式 |
| --- | --- | --- |
| 收藏、历史、漫画页码、视频最近进度 | 三板块的库行随配置备份导出 | 新建空目录恢复，比较导出前后的完整记录 |
| 逐集视频断点 | 本地备份与 iCloud 都包含 | 同作品多集、两个源同 ID、清除历史的云端删除标记 |
| 收藏分组、板块偏好 | 随阅读设置恢复 | 重开数据库及空目录恢复 |
| 手工媒体库 | 备份媒体条目及其剧集元数据 | 恢复后比较 JSON |
| 普通源 | 脚本、用户命名、分组、启停、镜像、图片及视频线路、非敏感扩展选项 | 使用真实脚本引擎恢复到新目录 |
| 普通订阅 | 启停、成员、排除列表 | 空设备文件内容比较，非法字段预检 |
| Node 猫源 | 订阅 ID、站点元数据、收藏与历史、布局，以及已安装的程序与配置文件 | 本地猫源包的 MD5 校验及空设备恢复 |
| 登录凭据与隐私锁 | 源账户密码、Cookie、敏感扩展选项和历史锁不导出；钥匙串不复制 | 明确检查备份不包含测试凭据 |
| 已下载媒体、本地模型、缓存 | 不属于配置备份 | 界面明确说明范围 |

单个全局 JSON 损坏会跳过该文件并提示原因，其他有效数据仍可备份。缺少本地猫源程序包的订阅会明确提示并跳过。源恢复因运行时或板块不支持而跳过时，界面会提示数量。恢复过程遇到 I/O 或源导入失败可能已应用部分数据，可使用恢复前快照重试恢复；跨多个文件和数据库的恢复不宣称为一个原子事务。

## 启动与故障排查

- 启动先显示加载页，每项设置有超时保护，失败时列出项目并提供重新加载。非关键项目失败允许继续；隐私初始化失败不开放应用内容。
- 异常日志最多持久化 80 条、128 KiB，限制单条长度；落盘前脱敏凭据、URL 路径与本机路径。日志页面和诊断包可查看上次异常，清空日志同时清理磁盘副本。
- 播放诊断记录内核创建、回退、媒体载入及失败阶段、域名和耗时，不保存播放路径、查询串或请求头内容。诊断包包含这组元数据。
- 缓存统计、清理、修剪和漫画图片保存、下载采用异步文件操作。大目录测试同时验证事件循环仍能运行，保存图片目录与其他板块不受清理影响。
- 隐私配置写入串行执行，每次写入合并最新状态，避免临时文件冲突。

## 全局流畅度补查

历史列表原来在一次构建中先读取全部作品，再为每条记录分别查询进度和收藏状态。现在由 SQLite 的一次关联查询筛选历史，并为板块与更新时间建立索引，减少大量收藏下的重复主线程查询。诊断导出读取配置文件也改为异步。

页面层的磁盘递归统计、漫画保存和下载、启动等待已纳入本次检查。播放、图片解码及毛玻璃动画的实际帧耗时依赖设备 GPU、原生插件与数据规模；现有桌面 widget 回归只能验证布局和行为，不能证明 iPhone 全局保持某个帧率。后续真机 profile 应分别记录冷启动、长列表滑动、漫画连续翻页、切集与大缓存清理期间的 UI/raster 帧耗时。
