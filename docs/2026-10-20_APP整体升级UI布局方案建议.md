# APP 整体升级：UI 布局与排版方案建议

- 日期：2026 年 10 月 20 日（北京时间）
- 性质：**讨论稿**，只给方案与取舍，不改应用代码、不启动整体升级。
- 前提：小说模块已移除，当前底部为漫画／视频／猫源／设置四个入口；液态玻璃改造已完成；整体升级此前暂停，由用户重新确定范围。
- 已有素材：交互预览 `build/lumebox-redesign-preview.html`（之前的三套：轻盈内容／秩序书库／沉浸画廊，早于小说移除）；本文件在它们基础上细化，并新增第四套“来源工作台”。
- 概念板：`build/design-schemes-board.png`（四套首页结构对照，非像素级设计稿）。

---

## 0. 结论摘要

1. **LumeBox 的核心差异不是“书架”，而是“多来源的内容入口”**：漫画、视频、猫源各有自己的源列表、目录与播放/阅读器。整体升级如果只做视觉风格，容易变成“更好看的普通追番/漫画 App”；建议把“来源”提升为一级信息结构。
2. **推荐路线：以“轻盈内容”的留白与排版为骨架，吸收“来源工作台”的来源切换与分区，不做整站重写**。即：首页/板块页的头部与信息层级重做，浏览布局、播放器、阅读器、设置里的既有能力保留。
3. 排版上最值得先统一的是：**页面级字号从 20 提到 22–24、正文 14→15、说明 12 保持但降低字重、行高提升到 1.45–1.55、数字/时间用等宽变体、标题统一最多 2 行**。CJK 下现有 12pt 说明文字在高密度卡片里偏挤。
4. 四套方案的开发量排序：轻盈内容 < 秩序书库 ≈ 沉浸画廊 < 来源工作台；风险排序：沉浸画廊（性能/可读性）> 来源工作台（信息架构改动）> 秩序书库（密度与疲劳）> 轻盈内容（改动最小）。

## 1. 现状盘点（决定方案边界）

| 维度 | 现状 |
| --- | --- |
| 导航 | 底部 4 tab：漫画／视频／猫源／设置；设置里的导航栏可配可见项与顺序；液态玻璃已实现 |
| 板块页 | 每个板块共用阅读 Hub：玻璃标题栏 + 来源切换 + 收藏入口 + 分类/发现/筛选；浏览布局支持双列列表与三/四/五列网格（`BrowseLayoutMode`） |
| 内容组织 | 以“来源”为单位：每个源有自己的分类、列表、详情、选集；猫源是独立一套 |
| 排版 | `LumeTypography`：页面标题 20 / 区块标题 18 / 标题 16 / 正文 14 / 说明 12 / 展示 32、28、24；行高 1.3–1.5 |
| 视觉 | 液态玻璃 + 彩色海报 + 圆角卡片（12/16）；浅深色主题、强调色可换、字体可换（含粗体/斜体开关） |
| 设置 | 模块化设置页 + 独立的底栏/图标/播放器/语音/缓存等二级页，选项已经很多 |
| 播放/阅读 | 视频双内核、漫画阅读器、猫源 WebView、音频播放器；这部分不建议在整体升级里重做 |

约束：现有用户的导航顺序、浏览布局、主题、图标、源配置都必须保留；升级应可回退、可分阶段上线。

## 2. 设计目标与原则

1. **来源优先**：用户打开 App 的第一动作通常是“在某个源里找内容”，不是“逛一个通用首页”。来源切换要显眼但不喧宾夺主。
2. **内容优先**：封面/海报是最大的视觉资产；文字排版服务于“扫读”，不是展示字体。
3. **层级克制**：一屏最多三层信息（页面标题 → 分区 → 卡片）；玻璃材质只用于 Chrome（顶栏、底栏、浮层），不铺满内容区。
4. **CJK 友好**：中文标题避免全大写/过多字重对比；数字、集数、更新时间用 tabular figures；长标题统一两行截断。
5. **可达性**：大字号、粗体、减少动态效果、深色模式必须一起验收；任何方案都要能在 320–440pt 宽度与大字号下不溢出。

## 3. 四套方案

### 方案 A：轻盈内容（Light Content）——推荐作为骨架

**定位**：留白多、层级少、封面大；像“杂志目录”，不是“仓库”。

**首页 / 板块页结构**

```text
┌────────────────────────────┐
│ LumeBox            ⌕   ⚙  │  品牌行 + 搜索/更多
│ 漫画                       │  页面标题 24–26pt（可随滚动收起）
│ [当前来源 · 樱花漫画  ⌄]   │  来源胶囊（一级入口）
│                            │
│ ┌────────────────────────┐ │
│ │  继续阅读 · 大封面      │ │  16:9 或 4:3 Hero（最多 1 个）
│ │  标题 / 进度 / 继续 →   │ │
│ └────────────────────────┘ │
│ 最近更新           全部 →  │  分区标题 18pt
│ ┌──────┐ ┌──────┐          │  双列卡片（封面 3:4）
│ │      │ │      │          │  标题 15pt 两行 + 说明 12pt
│ └──────┘ └──────┘          │
│ ┌──────┐ ┌──────┐          │
│ └──────┘ └──────┘          │
│ 分类浏览           全部 →  │  横向 chips 或 3 列入口
│ [热血][日常][科幻][更多]   │
│                            │
│  ⌂ 漫画   ▶ 视频   🐾 猫源  ⚙ 设置 │  液态玻璃 Dock
└────────────────────────────┘
```

**排版**：页面标题 24 (w600)；Hero 标题 20 (w600)；分区标题 17–18 (w700)；卡片标题 15 (w500)，说明 12 (w400)；行高 1.4–1.5。

**优点**：改动集中在头部与首页分区，现有卡片/网格/来源页可直接复用；视觉提升明显；性能风险低。
**缺点**：信息密度低，重度用户要多滚动；“继续阅读”对多源场景的表达有限。
**开发量**：中（主要改 `ReadingHubPage`/`SourceHomeView` 的头部与首屏，新增 Hero/继续入口）。
**风险**：Hero 数据来源需要跨源聚合，第一期可只取当前源。

### 方案 B：秩序书库（Ordered Library）——适合“收藏/追更型”用户

**定位**：高密度、强秩序、像书架/索引；一屏看更多，适合多收藏、多分类。

**首页 / 板块页结构**

```text
┌────────────────────────────┐
│ 漫画 · 秩序      ⌕   ☰    │  紧凑标题行 20pt + 布局切换
│ [全部][收藏][历史][更新]   │  分段 tabs（可横滑）
│ 来源：樱花漫画 ⌄   筛选 ⌄   │  来源与筛选合并一行
│ ┌────┐┌────┐┌────┐         │  三列海报（可切 4/5 列）
│ │    ││    ││    │         │  封面 3:4，圆角 10
│ └────┘└────┘└────┘         │  标题 13pt 两行，集数 11pt
│ ┌────┐┌────┐┌────┐         │
│ └────┘└────┘└────┘         │
│ ┌────┐┌────┐┌────┐         │
│ └────┘└────┘└────┘         │
│  ⌂ 漫画   ▶ 视频   🐾 猫源  ⚙ 设置 │
└────────────────────────────┘
```

**排版**：页面标题 20 (w600)；分段标签 13 (w600)；卡片标题 13 (w500)、说明 11 (w400)；行高 1.35–1.45；数字/集数用等宽数字。标题最多两行，超出省略。

**优点**：密度高、扫读效率最好；与现有三/四/五列网格能力天然吻合；对追更用户友好。
**缺点**：视觉偏工具化，与液态玻璃的“轻盈”气质有冲突；12/13pt 中文在暗色封面上易疲劳；新用户可能觉得“信息过载”。
**开发量**：中低（主要是头部与分段、间距/字号 token 调整）。
**风险**：大字号下 4–5 列会过挤，需要自动降列；卡片文字对比度需按封面明暗自适应。

### 方案 C：沉浸画廊（Immersive Gallery）——适合“视频/视觉向”用户

**定位**：内容即界面；大图、横滑、边到边，Chrome 悬浮并自动隐藏。

**首页 / 板块页结构**

```text
┌────────────────────────────┐
│ ▓▓▓▓ 全屏海报/剧照 ▓▓▓▓    │  60–70% 屏高的 Hero，顶部渐变
│ ▓▓  标题 · 类型 · 集数  ▓▓ │  标题 26–28pt 白色 + 阴影
│ ▓▓  [继续观看] [详情]   ▓▓ │  两个玻璃按钮
│                            │
│ 为你推荐        · · · →    │  横向大卡（1.4 张露出）
│ ┌────────┐┌────────┐       │
│ │        ││        │       │
│ └────────┘└────────┘       │
│ 最近更新                   │  横向卡片继续
│ ┌────┐┌────┐┌────┐         │
│                            │
│      ▁▁▁▁ 液态 Dock（细）  │  滚动时收起，上滑浮现
└────────────────────────────┘
```

**排版**：Hero 标题 28 (w700)；分区标题 18 (w600)；卡片标题 14；正文 14；说明 12；白色文字加 0–30% 阴影；深色优先（浅色主题需要额外对比度策略）。

**优点**：视觉冲击最强，适合视频板块；与液态玻璃的“浮起透镜”气质最接近。
**缺点**：可读性与内容效率最低；浅色主题难做；大图 + 模糊/玻璃叠加对中低端机性能压力大；不适合漫画/猫源的列表浏览。
**开发量**：高（Hero、横向滚动、Chrome 自动隐藏、图片解码与缓存策略）。
**风险**：性能与耗电；大字号/浅色主题验收成本高；容易变成“只有视频板块能用”的方案。

### 方案 D：来源工作台（Source Workbench）——新增，最贴合 LumeBox

**定位**：把“来源”做成一级工作台；首页不是内容瀑布，而是“当前源 + 四个动作入口”。

**首页 / 板块页结构**

```text
┌────────────────────────────┐
│ LumeBox            ⌕   ⚙  │
│ 漫画                       │
│ ┌────────────────────────┐ │
│ │ 当前来源                │ │  大号来源卡（可点开切换）
│ │ 樱花漫画      切换 ⌄    │ │  显示源图标/延迟/收藏数
│ │ 最近更新 12 分钟前      │ │
│ └────────────────────────┘ │
│ ┌──────────┐┌──────────┐   │  2×2 动作入口（玻璃卡）
│ │ 继续阅读 ││ 我的收藏 │   │
│ │ 3 部     ││ 128 部   │   │
│ └──────────┘└──────────┘   │
│ ┌──────────┐┌──────────┐   │
│ │ 发现     ││ 更新日历 │   │
│ └──────────┘└──────────┘   │
│ 最近更新           全部 →  │  列表（紧凑）
│ ┌────┐ 标题 · 第 12 话     │
│ │    │ 更新时间 · 来源       │
│ └────┘                     │
│  ⌂ 漫画   ▶ 视频   🐾 猫源  ⚙ 设置 │
└────────────────────────────┘
```

**排版**：页面标题 22；来源卡标题 18–20 (w600)、副标题 12；入口卡标题 15、数字 20 (w700, tabular)；列表标题 15、说明 12。

**优点**：把“多源”变成产品优势；来源切换、收藏、更新一眼可达；对猫源/视频同样适用；与现有来源切换组件、订阅状态图标可复用。
**缺点**：信息架构改动最大，需要定义“当前源”的跨板块语义；首屏内容展示减少，可能不符合“打开就想看内容”的用户。
**开发量**：高（新首页骨架 + 各板块适配 + 迁移旧的首页布局/入口）。
**风险**：概念需要用户验证；若来源多且不稳定，来源卡容易变成“负担”。

## 5. 排版与间距建议（三套方案共用底座）

### 5.1 字号阶梯（建议替换现有 `LumeTypography`）

| 角色 | 现在 | 建议 | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- | --- |
| Display | 32 | 32 | w700 | 1.2 | 空状态/大数字 |
| Page title | 20 | 22–24 | w600 | 1.3 | 板块页标题 |
| Hero title | — | 22–26 | w600 | 1.25 | 大卡标题（最多 2 行） |
| Section title | 18 | 17–18 | w700 | 1.35 | 分区标题 |
| Card title | 16 | 15 | w500 | 1.4 | 卡片/列表标题（2 行） |
| Body | 14 | 15 | w400 | 1.5 | 详情正文/设置说明 |
| Caption | 12 | 12 | w400 | 1.45 | 集数/时间/来源 |
| Label | — | 12 | w600 | 1.3 | 胶囊/按钮小标签 |

要点：
- 中文标题不要用 700 以上字重铺满全屏；强调靠字号与颜色，而不是再加粗。
- 集数、更新时间、进度数字使用 `FontFeature.tabularFigures()`，避免跳动。
- 长标题统一 `maxLines: 2`；列表类只保留 1 行 + 省略，详情页再展开。
- 所有字号继续走 `InterfaceTextScaler`，与系统无障碍缩放相乘，不做整页固定缩放。

### 5.2 间距与栅格

- 8pt 基准：4 / 8 / 12 / 16 / 20 / 24 / 32；页面左右边距 16（窄屏 12）。
- 分区之间 24；卡片之间 12；卡片内边距 10–12。
- 圆角：小控件 8–10、卡片 12、大卡/弹层 16–20；液态玻璃 Dock 继续用现有参数。
- 卡片比例：漫画/海报 3:4；视频横卡 16:9；列表行高 72–88。
- 底部安全区：Dock 高度 54–60 + 内容底部留白 ≥ 96，避免最后一行被 Dock 遮挡。

### 5.3 颜色与材质

- 内容区背景保持低饱和（浅色 #F6F4F8 / 深色 #121214 附近）；玻璃只用于顶栏、Dock、浮层与按钮。
- 强调色用于选中态、进度、可点击文字，不用于大面积背景。
- 封面上的文字必须有可读性兜底：底部渐变遮罩或 70% 不透明底条，深色主题同理。

## 6. 推荐落地顺序（若采纳 A + D 混合）

**阶段 1（低风险，先做）**：统一排版 token + 各板块页头部（标题、来源胶囊、搜索/更多收纳）+ 首页首屏“继续阅读/最近更新”分区。保留现有卡片与网格、全部功能入口。
**阶段 2**：把“当前来源”卡片化（方案 D 的核心），先在一个板块（建议漫画）验证来源切换与“继续/收藏/发现/更新”四入口，再推广到视频/猫源。
**阶段 3**：按板块选择呈现方式：漫画默认双列卡片、视频可选沉浸横滑、猫源保持现有站点网格；设置页只做分组与排版统一，不动能力。
**阶段 4**：预览与真机验收：浅/深色、320–440pt、大字号、减少动态效果、iPhone 帧率与滚动性能；确认后再决定是否默认开启。

不建议一期同时做“沉浸画廊”的大图 Hero 与横向大卡：性能与验收成本最高，可以留到阶段 3 作为视频板块的可选样式。

---

## 7. 需要用户确认的点

1. 产品气质更偏“轻盈杂志”（A）还是“高效书库”（B）？这决定字号与密度。
2. “来源”是否作为一级入口（D 的来源卡）？如果多源是核心卖点，建议采纳。
3. 视频板块是否要做沉浸式大图（C）？如果要做，是否接受性能与浅色主题的额外工作。
4. 首页是否需要“继续阅读/继续观看”聚合（跨源还是当前源）？
5. 是否保留现在的浏览布局切换（双列列表 / 三/四/五列网格）作为用户可选项。
