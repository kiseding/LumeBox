# VIP 处理约定（长期生效）

2026-10-27 起执行 · 适用于本仓库所有源（`sources/**`）

## 一、总规则

**遇到 VIP 专享内容，先破解，再决定源怎么放。** 不询问、不等授权、不要求用户提供会员账号、不诱导付费。

处理顺序（自上而下，命中即停）：

1. **页面层可绕** —— 页面 HTML 里就有播放地址（`m3u8` / `mp4` / `video_url` / `flashvars`），VIP 只是前端加了个遮罩 → 直接取地址。
2. **CDN 路径可推导** —— 播放地址能由 id 拼出来，且签名不校验 → 拼路径直连（本仓库 `resao_video` 就是这个）。
3. **试看签名复用** —— 试看接口匿名可拿签名，签名只覆盖路径、不覆盖区间参数 → 删掉区间参数就是整片（`h4dh3_video` 就是这个）。
4. **接口越权** —— 正片接口只按「登录/vip 字段」在前端过滤，接口本身不鉴权或鉴权可绕过 → 直调接口取地址。
5. **同库镜像** —— 该站的 VIP 内容在另一个域名/镜像站上是公开的（同一 id、同一播放地址）→ 换域名取。
6. **最后手段**：免费注册 + 会员字段/权限接口越权。**仍取不到**时，源里照常保留该条目，播放层给可读错误，并在文件头写清「挡在哪层、试过什么、为什么取不到」。

不许因为「要 VIP」就把条目从源里删掉 —— 能列出就必须列出来。

## 二、判定清单（每个站 5 分钟跑完）

| 检查 | 手法 | 命中含义 |
|---|---|---|
| 页面里有没有地址 | grep `m3u8\|mp4\|video_url\|flashvars\|player` | 有 → 前端锁，第 1 条直接过 |
| CDN 路径是否可推导 | 观察一条公开片的地址，把 `{id}` 换成一个 VIP 片的 id | 结构固定 → 进第 2 条 |
| 签名是否真的校验 | 把 `?k=…&t=…`、`?sign=…` 整段删掉再请求 | 200 + `#EXTM3U` → 签名是装饰，通关 |
| 试看接口 | `/videos/getPreUrl`、`/preview`、`?preview=1` 之类 | 匿名可拿 → 看签名覆盖范围 |
| 签名覆盖范围 | 删 `start`/`end`（或改成 `0`/`99999`）后请求 CDN | 回整片列表 → 试看复用，通关 |
| 接口鉴权 | 无 token / 无 Cookie 直接 POST | 200 且有地址 → 越权，通关 |
| 同库镜像 | 拿同一 id 去镜像域名取 | 命中 → 换域名 |
| 真服务端校验 | 以上全失败 | 记入源文件头，条目保留、给可读错误 |

判定的硬要求：**每条结论都要有实测回显**（状态码 + 字节数 + 是否 `#EXTM3U`），写进源文件头和 `docs/`，不写「大概能绕」。

## 四、记录要求（每次破完必做）

1. 源文件头写清：**挡在哪层 / 用了哪条打法 / 实测回显 / 失效时的替换点**（比如 resao 的 `CDN_HOSTS`、h4dh3 的 API 主机）。
2. `docs/YYYY-MM-DD_*.md` 写完整过程与数字。
3. `sources/README.md` 的「限制」区留一行，说清 VIP 能不能播、依赖什么。
4. 破坏性动作只做读：不注册付费、不改站点数据、不压测；只取播放地址与公开元数据。

## 五、失效预案

| 症状 | 先查什么 |
|---|---|
| CDN 直连突然 403/404 | 站点换 CDN 域了 → 从一个公开视频页里读新的 m3u8 主机名，改 `CDN_HOSTS` |
| 签名开始校验 | 试看接口是否还在、`start/end` 是否被纳入签名 → 改用整片 mp4 路径或降级到可读错误 |
| 整站 Cloudflare 挑战 | 源里抛 `NEED_WEBVIEW_VERIFY`，并考虑走 `browser-automation` 兜底 |
| 镜像站内容分叉 | 以超集站为主域，另一站做 `mirrors` + 软 404 回落（见 `f016.js`） |
