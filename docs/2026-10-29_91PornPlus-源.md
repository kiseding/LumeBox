# 91PornPlus 源：网页被 RST，但 `POST /js` 接口国内直连，匿名就给 m3u8

2026-10-29 · `sources/video/91pornplus.js`（`porn91plus_video`）

## 一、先回答「能不能破解」

**不用破解。** 这个站的前端是 Angular SPA，网页本体在国内被 RST，但它自己的数据接口
（`https://v2.<域名>/js`）国内直连 200，而且**匿名**请求就返回播放地址：

- 列表 `/sevenVideos?page=1&type=home_91_8` → 24 条，含标题/封面/时长/播放量；
- 详情 `/sevenVideos/<id>` → `m3u8s: ["https://tm.pppsuccess.com/<token>,<ts>/<id>/index.m3u8"]`，
  实测 200 + `#EXTM3U`，**不需要登录、不需要 VIP、不需要 Referer**；
- 抽样 24 条（含「国产VIP」「欧美(VIP)」「日本AV」「重口味」栏目）**全部**匿名拿到 m3u8。

所以源里没有任何「解锁 / 绕付费 / 试看转全片」的处理：只是按网页自己的调用方式请求接口。
如果以后某条视频要求登录，脚本会退化成 `webplayer`（交给 App 内嵌浏览器），不会伪造凭证。

## 三、协议：单入口 + 加密响应

```
POST https://v2.<host>/js
Content-Type: application/json
Origin: https://www.91pornplus.com        ← 必须有（或 Referer）
Referer: https://www.91pornplus.com/

{"app":"91pornplus.com","isStandalone":false,
 "theLink":"https://rs.pppsuccess.com",   ← 非空即可（实测任意 URL 都收，空串 403）
 "uuid":"U202610292109444095",             ← 必须 U+YYYYMMDD+HHMMSS+4 位（只校验形状）
 "url":"<接口路径>","version":"260901",
 "deviceInfo":{...}}
```

响应 `{"r":"U2FsdGVkX1…"}` 是 **crypto-js `AES.decrypt(r, "xxx")`**：

- `Salted__` + 8 字节 salt + 密文（OpenSSL 格式）；
- key/iv = `EVP_BytesToKey(MD5)`：`D1 = MD5(pass+salt)`、`D2 = MD5(D1+pass+salt)`，
  key = `(D1‖D2)[0..32]`、iv = `(D1‖D2)[32..48]`；
- AES-256-CBC + PKCS7。

沙箱里没有 `atob` / `Buffer` / `crypto`，所以脚本内联了纯 JS 的 Base64、MD5、AES-256-CBC
（约 300 行）。**验证方式**：用同一份线上密文，纯 JS 实现与 Node `crypto` 的
`aes-256-cbc` 输出逐字节相等（4843 B 的 JSON 完全一致），MD5 另用空串/abc/中文四组对照。

实测「必须带的头/字段」矩阵（少一个就 403 `{"blocked":true}`）：

| 组合 | 结果 |
|---|---|
| 无 Origin 也无 Referer | 403 |
| 只有 Origin 或只有 Referer | 200 |
| `theLink` 为空 / `uuid` 形状不对 | 403 |
| `uuid` 用昨天/下周/随机 4 位 | 200（只校验格式） |
| `app` 换成 xchina.tube / porntube.cool | 200（同一套数据） |

## 六、限制

- 网页本体在国内打不开，「打开站点」会失败；列表与播放不受影响（都走接口/CDN）。
- 单条视频只有一档 m3u8（`m3u8Type:"m3u8"`，`m3u8s` 长度 1），没有多清晰度可选。
- 播放地址带时间戳令牌，所以每次播放都现取详情，不缓存。
- 接口要求 `Origin`/`Referer` 与 `uuid` 形状；站点改校验规则时脚本会报「blocked」或
  「密文解不开」，不会是空列表。
