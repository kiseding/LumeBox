# 有声小说导入与订阅同步排查

检查日期：2026-10-25。

## 仓库检查结果

线上 `LumeBox-Sources/main/audiobooks` 包含四个有声源地址；线上 `videos` 也包含这四个地址。四份脚本存在，JS 语法检查通过，因此本次问题不是听书清单漏发布。

`all` 的内容是 `lume.total-subscription` 格式的 JSON，并非“一行一个地址”的清单。过去只有专门的总订阅页面认识这种格式，普通源导入和订阅同步没有正确展开它。本次增加了按目标板块展开的支持，视频入口只读取视频订阅，漫画入口只读取漫画订阅，停用项跳过。

仓库里的其他旧清单、源站播放能力和各网络出口不在这次“听书文件是否已发布”的结论之内。下载失败需看具体 HTTP 或网络错误，不能按“新增 0”判断仓库没有更新。

## 新入口

新包：视频源抽屉 → “+” → **有声小说源**。弹窗预填：

```text
https://raw.githubusercontent.com/teng662858/LumeBox-Sources/main/audiobooks
```

导入后定位到“有声小说”分类。已订阅 `videos` 的用户也能通过更新该订阅获取四站。

旧包可以从“普通视频源”的订阅导入入口粘贴上述地址；旧包不会因为源仓库更新而自动出现新按钮。专用入口和同步逻辑修复需要安装包含本次修改的新包。

## 同步行为

- 手动同步若碰上后台检查，会等后台任务结束后执行强制刷新，不会复用后台因六小时冷却而跳过的结果。重复点击合并到同一次强制任务。
- 同步显示已检查订阅数、未变化源数及实际失败链接和原因。未启用任何订阅、当前平台不支持运行源时，也明确说明，不再只有“新增 0”。
- 一个脚本下载失败仍继续其他脚本，保留原有源；损坏的总订阅不触发旧源移除。
- “全部订阅”指已经保存且启用的订阅。仅导入过单条脚本、不存在对应清单订阅时，需要先添加一次清单地址；不自动替用户添加第三方订阅，也不恢复手动删除的源。

## 仍然失败时查看什么

在同步结果中复制失败地址和错误文字。HTTP 404 表示对应地址不存在；HTTP 429 表示请求过于频繁；超时或 DNS 错误表示当前网络没有取到该文件。镜像地址可能存在缓存，需同时核对正在同步的实际地址。
