# 源设置保存后的首页失败与登录态失效

## 1. 保存站点地址后首页立刻报「脚本错误：请求已取消」

保存会重写图源记录（换地址、换 UA/Cookie），引擎运行时随之重建。旧运行时在
`SourceWebRuntime.dispose()` 里 `cancel()` 了自己的一生，**仍在飞的首页请求**于是以
「请求已取消 / 源已释放」结束，被界面当成真实失败显示。

修法：`SourceHomeView._load` 把这类「被替换」错误视为瞬时状态，等 150ms 后**自动重来
一次**；第二次仍失败才显示错误卡。用户不再需要手点【重试】。

## 2. 登录后进入阅读页无效

`LumeHttp._headersFor` 在提交 `bf2d0cc`（10-21「harden session cancellation」）里引入
`_legacySessionHost`：**只允许第一个请求过的 host 带会话 Cookie 与图源 Cookie**。
同一个源常见多域协作（`www.` / 裸域 / `api.` / `img.`），甚至换站址后旧 client 的钉子
还在旧域——于是：

- 登录拿到的 `cf_clearance` / 登录 Cookie 只对第一个 host 生效；
- 阅读页走的是另一个子域 → Cookie 被丢弃 → 页面看起来「没登录」。

修法：把「等于钉住的 host」放宽成「同一站点树」。判定用注册域近似：

- `www.example.com` / `api.example.com` / `example.com` → 同站；
- `evil-example.com` → 不同站（仿冒域不放行）；
- `com.cn` / `co.uk` 这类两段后缀多取一级，避免把两个不同二级域当成同站。

回归用例见 `test/http_header_regression_test.dart`：
「会话 Cookie 在同一站点树内放行」与「会话 Cookie 不发给别的站点」。
