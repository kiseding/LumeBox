# 离线音色包改为在线下载

2026-10-31。本文取代 [2026-10-29 离线资源精简](2026-10-29_离线资源精简与网页整剧.md) 里「音色包在 build 期重打包」那一节。

## 结论

音色包的权重不再进安装包，也不再进仓库。库里只留 `manifest.json`，用户第一次启用离线朗读时按清单从模型官方发布页下载七份文件（合计 123,661,958 字节 ≈ 118 MiB），逐份校验 SHA-256 后装进原来的目录。

| 位置 | 变化 |
|---|---|
| 未签名 IPA | −110.43 MiB（build 期生成的 `runtime/` 不再打包） |
| 仓库工作区 | −140.12 MiB（`pack.00`–`pack.04` 删除） |
| 首次启用时下载 | 123.7 MB（一次性，装好后完全离线） |

注：删文件不会缩小已有的 git 历史，`git clone` 的体积不变；要缩小只能重写历史，不建议。

## 为什么下载源可以直接用别人的

`vits-zh-aishell3` 的运行时文件本来就托管在模型发布页上，而且与仓库里那份**逐字节相同**：

- `vits-aishell3.onnx`（121,383,104 字节）在 Hugging Face 的 LFS 摘要
  `c37544d4…6fdcae` 与 `manifest.json` 里的 `files[].sha256` 一致。
- `tokens.txt`、`lexicon.txt`、`date.fst`、`number.fst`、`new_heteronym.fst`、`phone.fst`
  六份小文件实测下载后 SHA-256 与清单逐条相符。

因此不需要重新托管、不需要自建对象存储，`manifest.json` 的 `sources` 直接写发布页地址：

```json
"sources": [
  "https://hf-mirror.com/csukuangfj/vits-zh-aishell3/resolve/main/",
  "https://huggingface.co/csukuangfj/vits-zh-aishell3/resolve/main/"
]
```

国内先走镜像、再回官方站点。要换成自有存储，改这一个数组即可，代码不用动。

## 代码

- `lib/core/speech/speech_local.dart`：`prepare()` 分成两条路——手动导入走原来的
  `tar.bz2`（校验 `archiveSha256`，只抽清单里的七个文件），否则按 `sources`
  逐份下载；全部到齐且 `_valid` 通过后才替换已安装目录，中途失败不碰旧模型。
  新增 `received` / `total` 两个字段给界面显示百分比。
- `lib/core/models/model_source.dart`：新增 `fetchFrom()`，支持多地址依次尝试与
  HTTP `Range` 断点续传（121 MB 的单文件掉线后不用从头再来）；摘要不符会删掉
  临时文件再换下一个源，不会把坏字节续进正式文件。
- `pubspec.yaml`：`assets/speech/vits_aishell3/runtime/` 移除，只留 `manifest.json`。
- 删除 `tool/prepare_speech_assets.py`、`tool/test_compact_assets.py` 与
  `assets/speech/vits_aishell3/pack.*`；`build-ios.yml`、`tool/check_quality.ps1`
  对应步骤一并移除。
- 文案：按钮改为「启用离线音色包（约 124 MB）」，下载中显示百分比，对话框与
  使用说明如实写明需要联网下载、失败可从文件安装。

## 测试

`test/speech_local_model_test.dart` 改为注入假清单与假下载器，不再依赖仓库里的
大权重，也不联网：覆盖「按清单下载并校验」「坏包导入保留已装模型」「下载失败
不动已装文件」「选择器取消与平台异常」。

真实下载路径本机未能端到端验证（下载 121 MB 后交给 sherpa-onnx 推理需要真机），
以 CI 构建 + 真机首次启用为准。
