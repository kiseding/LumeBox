# 新增三个源：天撸啦（视频 / 图集 / 小说分开，共用一套解密）

2026-10-27 · `sources/video/tianlula.js`、`sources/photo/tianlula.js`、`sources/comic/tianlula-novel.js`

## 1. 为什么拆成三个源

`https://ttbd067.top:51000/home` 是天撸啦（tianlula.tv）—— 综合站，三类内容走两套接口、两种读法：

| 内容族 | 接口 | 量级 | 读法 | 落到哪个源 |
|---|---|---|---|---|
| 视频（精品视频 37 + 电影频道 1） | `Api-vod_list` / `Api-vod_search` / `Api-vod_detail` | **284,145** | 播放器 | `video/tianlula.js` |
| 图集（成人图片 3，9 个子分类） | `Api-news_list&type=pic` / `Api-news_detail` | 2,415（cid=22） | 图片阅读器 | `photo/tianlula.js` |
| 小说（小说专区 2，9 个子分类） | `Api-news_list&type=text` / `Api-news_detail` | 2,148（cid=13） | 文本阅读 | `comic/tianlula-novel.js` |

按《源拆分判据》：不同板块 / 不同读法 / 不同接口 → 拆源；同一接口内的分类用 `categories` 表达（视频源 52 个分类、图集与小说各 9 个），不再细分。

## 2. 前置条件：接口是 AES 密文

`/res?s=Api-xxx` 的返回体长这样：

```json
{"code":1,"page":1,"limit":2,"total":284145,"total_page":142073,"list":"7avyYJO75Pc2kaRuB02yRc0NN8obDa…"}
```

`list`（详情接口是 `data`）是 **base64 的 AES-128-CBC(PKCS7) 密文**（解码后长度是 16 的整数倍，无 zlib/gzip 头）。

取 key 的办法：`assets/core.js` 是 obfuscator 混淆的，静态搜不到 `CryptoJS.AES.decrypt`；改成**运行时挂钩**——在页面加载前注入脚本包装 `CryptoJS.AES.decrypt`，把参数打出来，一次就拿到：

```
key = bfd7257d9bee742c   （ASCII 16 字节 → AES-128）
iv  = 506ecf5490eeb552
```

LumeSource 沙箱里没有 `crypto` / `atob`（`tools.base64Decode` 返回的是 UTF-8 字符串，二进制会失真），所以三个源各自内联了一份**纯 JS 的 AES-128-CBC 解密**（S 盒 + 密钥扩展 + InvShiftRows/InvSubBytes/InvMixColumns + CBC + PKCS7 + 自写 base64/UTF-8）。验证方式：

- FIPS-197 结构自检；
- 与 Node `crypto.createDecipheriv('aes-128-cbc', …)` 对同一段站点密文逐字节比对：**660 字符完全一致**；
- 站点真实数据解出的 `vod_name` / `news_content` 中文正常。

## 3. 接口清单（实测）

```
GET /res?s=Api-list_all                                   → 顶层 4 类，子分类在 children 里
      37 精品视频（children 37 个）/ 1 电影频道（15 个）/ 2 小说专区（9 个）/ 3 成人图片（9 个）
GET /res?s=Api-vod_list&limit=20&page=N                    → 全站视频，total 284,145
GET /res?s=Api-vod_list&cid=71&limit=20&page=N             → 分类过滤（cid=71 total 3,572）
GET /res?s=Api-vod_search&wd=探花&limit=20&page=N          → 搜索（total 7,718，hasMore 字段）
GET /res?s=Api-vod_detail&id=306419                        → 详情，data 是密文，解出含：
      vod_url = https://m2.kdamao.com/hls/contents/videos/319000/319567/319567.mp4/index.m3u8
      vod_play = 999player，vod_gold = 9.0，vod_hits = 7
GET /res?s=Api-news_list&cid=22&type=pic&limit=20&page=N   → 图集，news_content 里是一整套 <img>
GET /res?s=Api-news_list&cid=13&type=text&limit=20&page=N  → 小说，news_content 是正文 HTML
GET /res?s=Api-news_detail&id=861009                       → 图文详情（data 是**明文对象**，不加密）
```

注：父分类 id（37 / 1 / 2 / 3）传 `cid` 会返回 `total=0`，只有子分类 id（71 / 22 / 13 …）有效；`Api-news_search` 不存在（返回 `code=0`），所以图集与小说源没有搜索。

## 4. 三个源

| 源 | id | 板块 | 关键实现 |
|---|---|---|---|
| `video/tianlula.js` | `tianlula_video` | 视频 | 列表/搜索/详情；`content` 直接给 `vod_url`（m3u8）；详情缓存 10 分钟 |
| `photo/tianlula.js` | `tianlula_photo` | 漫画·美图 | 列表拿 `news_content` 抽 `<img>`（统一 http→https、去重），`content` 返回 `kind: images` |
| `comic/tianlula-novel.js` | `tianlula_novel` | 漫画（kind text） | `news_content` 去标签转纯文本，`content` 返回 `kind: text` |

三个源分类都从 `Api-list_all` 现解析（按 host 缓存 6 小时），换域名/改分类都不用改代码。

## 6. 限制

- 站点换 AES key 时会抛「密文解不开（站点换 key 了？）」→ 重跑一次运行时挂钩取新 key/iv，改 `KEY_TEXT` / `IV_TEXT` 三处。
- 图集与小说没有搜索接口。
- 视频详情里的 `vod_url` 是 999player 线路的直给 m3u8（`m2.kdamao.com`），如换 CDN 会在详情里跟着变，脚本无需改。
- 小说列表单页载荷较大（20 条约 700 KB，因为 `news_content` 一起返回），详情缓存 10 分钟可减少重复拉取。
