## 1. 功能待办（按建议顺序）

### P1 · 播放器偏好接线（小而快，先把已有设置变成真实行为）

- **现状**：浏览器 UA、字幕语言、详情页“只选中不播放”可以保存，但没有接到实际运行行为。
- **目标**：
  - UA 真正传给内置播放器和网页视图；
  - 字幕语言用于选择默认/首选字幕轨；
  - “只选中不播放”在详情页只高亮选集、不自动起播。
- **验收**：改设置后无需重启立即生效；失败时回退默认值；现有播放器回归通过。
- **规模**：小。

### P1 · 网页主页源（已有入口，当前明确未接入）

- **现状**：视频源选择器已有“网页”分类和添加入口，点击提示未接入。
- **目标**：保存/编辑/删除主页地址；添加订阅后出现在选择器；点击打开内置 WebView 主页；返回 App 时状态保留；支持多个主页源与排序。
- **验收**：新增、编辑、删除、重启保留；打开/返回不丢页面；无网络/错误页有提示。
- **依赖/风险**：WebView 会话与 Cookie 已有基础；需要确认主页源与现有普通源/猫源的展示顺序。
- **规模**：中。

### P1 · 猫源 parse=1 网页解析

- **现状**：猫源返回网页解析地址（parse=1）时提示换直连线路，网页解析未接通。
- **目标**：识别 parse=1 地址 → 打开内置 WebView/解析接口 → 提取真实播放地址 → 交给播放器；失败时保留现有直连回退与提示。
- **验收**：至少覆盖两个真实猫源站点；解析失败可回退；不阻塞其他播放路径。
- **依赖/风险**：站点反爬、验证码、Cookie；不同站点解析规则差异。
- **规模**：中。

### P2 · Python 源（最大的一项，先做可行性验证）

- **现状**：源选择器已有 PY 分类和添加入口，明确未接入。
- **目标**：集成 Python 运行环境 → 导入 `.py` 文件或订阅 → 处理依赖 → 搜索/分类/详情/选集/播放；验证用户提供的《金牌.py》《影探4K.py》。
- **验收**：两个示例脚本能完成一次完整“搜索→详情→播放”；失败有可读错误；不拖慢 App 启动。
- **依赖/风险**：iOS 不能 JIT，需嵌入静态 CPython，体积和启动成本高；脚本依赖的第三方库需打包；沙箱与网络权限；先做技术 spike 再排期。
- **规模**：大。

### P2 · 模块源（先定协议）

- **现状**：已有“模块”分类和添加入口，明确未接入；尚未确定先兼容哪种模块协议。
- **目标**：选定协议（例如 T4/JS 模块/其他）→ 导入 → 宿主接口（网络、存储、播放）→ 目录/详情/选集/播放。
- **验收**：一个最小模块能从导入跑到播放；失败可回滚；不影响现有源。
- **依赖/风险**：协议选型是产品决策；与 T4 的“以后再说”结论相关，不能默认启动。
- **规模**：大（取决于协议）。

### P2 · 视频与猫源整合 / 底部三 TAB（已被暂缓）

- **现状**：视频页内已能切换普通源和猫源，但底部仍有独立“猫源”入口；两套存储独立。
- **目标**（如果确认）：猫源能力归入视频，底部改为漫画／视频／设置三 TAB；迁移猫源入口、订阅、收藏与隐藏配置；旧用户配置兼容。
- **验收**：三 TAB 下猫源功能可达；旧配置不丢；可回退到四 TAB。
- **依赖/风险**：属于 APP 整体升级范围，用户已明确暂缓；等待范围确认，不排开发。
- **规模**：中。

### P3 · 参考播放器服务入口

- **现状**：评论、DLNA、AirPlay 控件存在，提示未接入。
- **目标**：
  - 评论：确定评论服务来源后接入（当前无服务端约定）；
  - DLNA：设备发现 + 投屏；
  - AirPlay：系统路由入口（iOS 原生）。
- **验收**：控件不再是占位；无设备/无服务时有明确提示；不影响本地播放。
- **依赖/风险**：评论需要服务端或第三方 API；DLNA 需要局域网发现与协议实现；AirPlay 依赖系统 API 与真机。
- **规模**：中到大（按子项拆）。

### P3 · 生态扩展评估（不承诺接入）

- T4：用户已说“以后再说”，不启动。
- Stremio、Sora／Sulfur、Kazumi、Mangayomi：可评估，未确定协议。
- Emby／Jellyfin、OpenList／WebDAV、Audiobookshelf：个人媒体库/有声书库方向，需按移除小说后的产品范围重新评估。
- **结论**：这些只做评估，不排开发；需要用户先定产品范围。
