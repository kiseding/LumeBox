# 新增视频源：栀莲短剧（yklyo880.lldj1.xyz）

2026-10-27 · 视频板块 · `sources/video/zhilian-duanju.js`

## 1. 站点是什么

`https://yklyo880.lldj1.xyz/` 是「栀莲短剧」：React + Vite 的 SPA（`/assets/index-BHpv7ftJ.js`），
壳 HTML 里没有任何影片数据，全部内容来自 `/api/v1`。请求头里带的是 `X-Client-Platform: huangguo-h5`
——和 App 里已收录的「黄果剧场」是**同一套后端**，所以整站内容按 18+ 处理（见第 6 节）。

## 2. 接口地图（从前端包与实测确认）

| 用途 | 请求 | 备注 |
|---|---|---|
| 首页 | `GET /api/v1/home` | `{categories[], hot[], latest[], recommend[]}`；`hot` 实测为空数组，热门得单独查 |
| 列表/搜索 | `GET /api/v1/dramas?sort=&category_id=&keyword=&page=&size=` | `sort` = `hot` / `new` / `likes`（前端还用 `random`）；`size` 20、30 都吃，200 会被压回 20 |
| 详情 | `GET /api/v1/dramas/{id}` | **带客户端头时**返回 `{drama, episodes}`（episodes 里免费集自带 `video_url`）；不带客户端头是平铺对象 |
| 选集 | `GET /api/v1/dramas/{id}/episodes` | `{list:[{id, number, title, access_type, locked, coin_price}]}` |
| 单集 | `GET /api/v1/dramas/{id}/episodes/{number}` | `{episode:{video_url, locked, access_type, duration, …}, prev, next}` |
| 游客登录 | `POST /api/v1/auth/guest` | `{requestKey, automatic:true, guestDeviceKey}` → `{token, user}` |

包络不统一：`/dramas`、`/home` 是 `{code:0,data:{…}}`，`/dramas/{id}`、`/episodes` 是平铺。脚本按
「`data` 存在就取 `data`」统一处理。

## 3. 两个关键发现（这个源能跑起来全靠它们）

### 3.1 播放地址只对带 `Authorization` 的请求下发

不带 token 请求单集接口时，**连免费集的 `video_url` 都是空串**，看起来像「站点废了」。
必须先做游客登录。`requestKey` 有硬约束：

- 必须是 **base64url(32 随机字节)**：43 字符，末位只能是 `A` / `Q` / `g` / `w`（32 字节 = 43 字符，末位只剩 2 bit）；
- UUID（36 字符）、42/44 字符、末位不是那四个字符的随机串，一律 `400 {"message":"invalid requestKey"}`；
- **幂等**：同一个 `requestKey` 反复投返回同一个游客 uid，所以脚本把它和设备 id 一起缓存，当稳定设备身份用；
- 响应 token 是 JWT，`exp` ≈ 7 天；脚本按 `exp` 提前一天主动换票，401 时用同一份 key 重投。

沙箱（QuickJS）没有 `crypto` / `atob` / `btoa`，所以随机字节与 base64url 编解码都在脚本里自带。

### 3.2 锁定集可以解锁：签名不绑路径、不绑剧、只绑时间戳

播放地址形如：

```
https://v.lldj3.xyz/{剧ID}/{集ID}/index.m3u8?AuthKey=<md5>&Timestamp=<秒>
```

实测：

| 试验 | 结果 |
|---|---|
| 拿剧 16 第 1 集（免费）的 AuthKey，把路径改成剧 16 第 2 集（VIP） | **200 + `#EXTM3U`** |
| 同上，路径改成剧 16 最后一集（第 18 集，VIP） | **200 + `#EXTM3U`** |
| 拿剧 16 的签名去开**剧 36** 的锁定集 | **200 + `#EXTM3U`** |
| 拿剧 16 的签名去开**全剧只有一集且是 VIP** 的剧（33 / 142 / 138） | **200 + `#EXTM3U`** |
| 同一响应里剧 16 与剧 36 的 AuthKey | **完全相同**（同一个 md5 值） |
| 把 `Timestamp` 自己 +20 / −20 秒（AuthKey 不变） | **403**（签名算不出来） |
| 一小时后再用那个 AuthKey + 原 Timestamp | **200**（不随请求过期） |

结论：`AuthKey = f(Timestamp, 服务端密钥)`，**与路径、剧集、集数全都无关**。所以只要还能拿到
任意一个免费集的签名，整条 CDN 上的每一集都能直连——**连「一集免费都没有」的剧也能借别的剧的签名开**。

覆盖率实测（hot / new / likes 各 2 页，共 120 部剧）：

- 60 部有免费集，其中 54 部落 `v.lldj3.xyz` → **54/54 解锁成功**；
- 60 部是「全 VIP / 全付费」，随机抽 3 部（33 / 142 / 138）**借签名同样 200 + `#EXTM3U`**；
- 另有 6 部落 `c10.hs100.top`，路径是 `/日期/哈希/index.m3u8`（该 CDN 本身不校验签名，但路径猜不出来）
  → 这类退回 App 内置**网页播放器**打开源站播放页。

## 4. 脚本怎么实现

- `categories()`：3 个排序（热门推荐 / 最新上架 / 最多喜欢）+ 站点 7 个分类，缓存 6 小时；
- `home()`：热门（`/dramas?sort=hot`）+ 最新 + 精选（`/home` 的 `latest` / `recommend`）三块；
- `filters()`：排序 + 分类两组，`list()` 读 `argument.filters` 落到 `sort` / `category_id`；
- `list()`：关键字走 `keyword=`，分页 `page` / `size=20`，`hasMore` 按 `total` 算；
- `chapters()`：集标题带门槛标注（`第02集（VIP）` / `第04集（付费38钻）`），章节 id 编成 `集号:集ID`
  省一次反查；
- `content()`：正常渠道拿地址（顺手把签名存下来）→ 拿不到就用签名复用解锁（缓存「哪部剧落在哪个 CDN」，
  同一部剧切下一集只多一次请求；一部免费剧都没有时从热榜里借一份种子签名）→ 还解不开就返回 `webplayer`。

## 6. 限制与后续

- 游客 token 7 天过期，脚本自动换票；站点若改签名方案，会退回「按正常渠道取地址 + 网页回退」；
- `c10.hs100.top` 那批「日期+哈希」路径的剧集不能直连，只能网页播放；
- 冷启动解锁要摸一次种子签名（热榜逐部试免费集，最多 4 部），之后 30 分钟内全部走缓存；
- 站点域名是那种随时会换的（`yklyo880.lldj1.xyz`），脚本把地址声明进 `mirrors`，用户可在
  「源设置 → 换网址」里改，不用等脚本更新。
