## 导入 Python 或 JS 多文件源

把源的入口、辅助代码、资源及依赖放入同一个目录，在根目录保存 `lume.json`，然后导入 ZIP。文件导入、URL 订阅、订阅刷新、备份恢复均保存整个源包，不再依赖导入时的外部路径。

```json
{
  "entry": "main.py",
  "runtime": "python",
  "protocol": "spider",
  "metadata": {"id": "my-python-source", "name": "我的 Python 源", "version": "1", "category": "video"}
}
```

- Python：支持绝对及相对辅助模块导入、函数内部的延迟导入；多个源中同名辅助模块分开保存。源卸载时删除临时文件。
- 纯 Python wheel：把 `*-none-any.whl` 放入 ZIP，导入时展开；依赖的依赖也需一并提供。手机不运行 pip，不会根据 `requirements.txt` 自动联网安装。
- JS：把 `runtime` 改为 `module`，`entry` 改为入口文件；支持常见 ESM 导入导出、重新导出、字面量动态导入、CommonJS `require()`、JSON 和随包提供的 `node_modules`。本地文件采用扩展名及 `index.js` 等回退，包入口支持 `package.json` 的 `module`／`main`。
- JS URL 订阅：可直接订阅入口脚本，相对路径依赖自动递归拉取并保存为源包。相对依赖使用同站点的明确文件地址；裸包名依赖需随 ZIP 提供。跨站、同路径不同查询参数的模块请整理为 ZIP。
- JS 属于实用接口兼容层，不提供完整 Node.js 系统 API、ESM 活绑定或顶层 await；动态依赖路径须为字符串字面量。
- 整包解压后最多 8MB、256 个文件；拒绝路径越界、符号链接及手机端原生扩展安装。入口可以在子目录。
- `metadata` 可省略：优先沿用入口原有的 LumeSource 头部，否则按文件名／订阅地址生成身份。

## 使用 Python 本地代理

Spider 的 `getProxyUrl()` 返回绑定在 `127.0.0.1` 随机端口的私有地址，已带 `?do=py`，脚本可以继续追加 `&url=...` 等参数。播放器请求交给同一源的 `localProxy(params)`：

```python
def localProxy(self, params):
    response = self.fetch(params['url'], headers=params.get('headers', {}))
    return [response.status_code, response.headers.get('Content-Type', 'application/octet-stream'), response.content]
```

返回格式为 `[状态码, MIME, 文本或字节, 可选响应头, 可选Base64标记]`。第五项为 `1` 时第三项按 Base64 解码。支持 GET／HEAD、二进制、206、Content-Range 及重定向；请求头在 `params['headers']`，Range 也写入 `params['range']`。单次响应最多 6MB，长媒体应使用分段或 Range。停用、删除和释放源时关闭服务。

## 原生 Python 扩展

本次实际内置 `cryptography 47.0.0` 和 `cffi 2.0.0`，并加入纯 Python 依赖 `pycparser 2.23`。从 [BeeWare iOS wheel 索引](https://pypi.anaconda.org/beeware/simple/cryptography/)取得的 device／simulator wheel 分别记录版本、ABI、架构和 SHA256，详见 `tool/python_native_packages.lock.json`。

构建时按架构选择 wheel，把扩展转换为独立 framework、写入 `.fwork`／`.origin` 并签名。新增扩展需要提供适配 CPython 3.13 的 iOS wheel，更新锁文件后重新构建；带额外 dylib 的 wheel 要先完成框架依赖整理。不能把 Windows／Linux wheel 放进手机直接使用。这遵循 [CPython 的 iOS 原生模块打包要求](https://docs.python.org/3.13/using/ios.html#binary-extension-modules)。

## 接入其他 Spider 客户端或 Android 后端

JS Spider 源可在 `lume.json` 设置 `protocol: "spider"`，支持常见 `home`／`homeVod`／`category`／`search`／`detail`／`play`，以及 `homeContent` 等命名、异步函数和 JSON 字符串返回值。标准 `vod_*`、多线路、请求头、网页解析标记会转换到 App 的播放链路。不能根据方法名猜出所有客户端私有接口的语义。

Android Java／DEX 不在 iOS 本地执行。已有可运行这些脚本的服务端时，可导入以下 JSON 描述文件到模块源，App 负责调用与播放：

```json
{
  "format": "lume.remote-spider.v1",
  "endpoint": "http://127.0.0.1:9988/api",
  "transport": "t4",
  "metadata": {"id": "remote-spider", "name": "远程 Spider", "category": "video"}
}
```

示例地址在手机上表示手机自己；部署到 NAS／电脑时改成该设备地址。后端需由用户提供并保持运行，本次没有部署 Android 运行服务。

| transport | 请求 | 响应 |
| --- | --- | --- |
| `t4` | GET：主页 `filter`；列表 `ac=detail&t&pg&filter&ext`；搜索 `wd&quick&pg`；详情 `ac=detail&ids`；播放 `play&flag`。`ext` 为 JSON 文本 | Spider 常见 `class`／`list`／`vod_*`／`url` 字段 |
| `rpc` | POST JSON：`{"method":"homeContent","args":[true]}` 等 Spider 原始方法及位置参数 | Spider 对象，或 `{"ok":true,"value":对象}`；`ok:false` 作为失败 |

远端 T4 的 ext 编码、鉴权、站点选择和路径存在方言差异；目前实现表内约定，其他方言需明确协议后适配。Java／DEX 兼容取决于后端能力，不代表 iPhone 能直接加载 APK。
