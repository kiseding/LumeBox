# 小说模块移除

根据用户确认，仅移除小说朗读，保留漫画朗读。

后续用户补充要求保留独立音频内核：现已恢复 `just_audio` 播放底座、队列、进度、后台播放及音频设置，入口为“音频播放器”。小说板块、文本正文与小说朗读界面仍保持移除。下列验证数字为移除小说时的记录；后续修复见《底栏返回修复与音频内核保留》。

## 变更

- 删除小说首页、书架、目录、详情、阅读器、排版、书签及小说专用朗读界面。
- 删除小说板块标识、导航、设置、源分类、内置小说源和文本正文解析，以及本地文本导入和路由。
- 原小说体系的有声书入口已移除，独立纯音频页面现位于 `features/media/audio_player_page.dart`，音频文件通过媒体库进入，不依赖小说板块。
- 导航保留漫画、视频、猫源、设置；保留账户、iCloud 同步和全局框架。
- 漫画继续使用共享语音引擎、音色选择、后台朗读和内置离线模型。共享语音面板迁到 `lib/features/reading/speech_modes_panel.dart`，旧漫画音色设置兼容读取。
- 启动时清理旧小说的 `cache` 和 `reading_cache/images`。保留旧数据库及用户保存的图片，不触碰漫画、视频、猫源缓存。
- 旧总订阅、图源备份和配置备份中的小说字段自动忽略，其他板块正常导入。
- 小说移除时曾清理独立音频依赖；根据后续要求，现已恢复 `audio_session`、`just_audio`、`just_audio_background` 及 `audio_service` 路径覆盖供音频模块使用。
- 修复同一板块并发打开阅读数据库时可能创建多个句柄的问题，并补充回归验证。

## 验证

- `flutter analyze --no-pub`：无问题。
- `flutter test --no-pub --reporter expanded`：2009 通过，13 跳过，无失败。
- `flutter build windows --release --no-pub`：成功。
- 启动 Windows Release 进行 5 秒检查：进程持续运行，没有启动异常，随后关闭测试进程。

Windows 输出目录：`build/windows/x64/runner/Release/`，运行时需要保留其中的 DLL 和 data 目录。

相关日志位于 `build/novel-removal-tests-final.log`、`build/novel-removal-analyze-final.log`、`build/novel-removal-windows-final.log` 和 `build/novel-removal-startup.stderr.log`。

## 范围与遗留

- 本次是在 Windows 完成编译与启动验证，没有生成新的 IPA；用户此前下载的 1.0.166 IPA 不含本次移除。
- `third_party/audio_service_ownership` 现为独立音频模块使用的依赖，已恢复构建引用，需要继续保留。
