# 弹幕服务排查：内置本机服务 / 弹弹play 官方 / 自定义

- 日期：2026 年 10 月 22 日
- 用户反馈：内置服务器和弹弹play都加载不出弹幕、搜索无结果；自定义服务可以。

## 1. 先区分三种“弹幕源”

| 类型 | 实际走的地址 | 是否需要额外条件 |
| --- | --- | --- |
| 内置本机服务 | `lumebox://local-danmaku` → 手机内 Node 进程里的 bundled danmu_api | **仅 iPhone/iPad**；需要本地 Node 启动成功；首次构建包含它的版本从 1.0.182 才开始 |
| 弹弹play 官方 | `https://api.dandanplay.net` | **必须自己申请并审核通过的 AppId/AppSecret**，App 不内置共享凭证；无凭证返回 403 |
| 自定义 / 兼容服务 | 用户填的 `https://域名/路径` | 不需要官方凭证；只要该服务本身可用 |

“自定义可以、另外两个不行”符合上面的条件差异：自定义是普通兼容接口；官方缺凭证会失败；内置本机服务是本地 Node 路径，和普通 HTTP 服务不是一个实现。

## 2. 本次能确认的事实

1. **官方 403 已实测**：`https://api.dandanplay.net/api/v2/search/episodes?...` 不带鉴权返回 HTTP 403。官方要求 `X-AppId / X-Timestamp / X-Signature`，App 没有、也不应该内置他人的应用凭证。
2. **本地弹幕服务的桌面端到端已跑通**：
   - 用 Node 24 启动 `assets/cat/bootstrap.js` + `assets/local_danmaku/index.js`；
   - `/_health` 返回 200；
   - 带 token 的 `/api/v2/search/episodes?anime=花开锦绣&episode=1&v2=true` 返回 200 和真实作品/剧集；
   - 说明 adapter、token 校验、上游 danmu_api 在桌面运行环境下是通的。
3. **无法在 Windows 上验证 iPhone 上的 NodeMobile 运行时**：内置服务使用的是 iOS 的 NodeMobile lite 24.20.0；桌面验证不能代替真机。仓库 README 也明确写了“尚未在 iPhone 上验证全部平台命中、后台和画中画效果”。
4. **版本问题**：本地 `ipa/` 里最新的包是 `1.0.181`（10-21 12:07），而内置本机服务的代码提交在 10-22 00:25 之后；**1.0.181 不包含内置本机服务**。CI 有 1.0.182（10-22 00:39，commit `e29d2e0`）包含，但只要不是这个或更新的包，看到的内置服务就不是同一份代码。

## 3. 本次代码增强

- **官方 TMDB 补充失败不再拖垮搜索**：官方 `/search/episodes` 已经返回结果时，TMDB 补充接口失败（无权限、404、网络错误）只忽略补充，保留原生结果，不再整次搜索报错。
- **内置服务“测试连接”改为真实搜索探测**：以前只查 `/_health`，Node 活着但上游请求失败也会显示“连接成功”；现在会实际请求一次 `/api/v2/search/episodes`，上游 502/网络错误会直接显示。
- **上游错误原因透传**：本地 adapter 的 502 现在带 `errorMessage`；客户端也会解析非 200 的 JSON body 并显示原因（不再只有“HTTP 502”）。
- **本地启动错误原因透传**：内置服务启动失败时会带底层错误，而不是统一的“启动失败，请重试”。
- **超时放宽**：弹幕请求从 30s 放宽到 45s，给冷启动的本地 Node 更多时间。

## 4. 需要用户提供的信息（定位 iPhone 内置服务必需）

如果安装的是 1.0.182 或更新版本，仍然看不到弹幕，请提供：

1. 安装包版本（设置页/包名）与机型、iOS 版本；
2. 弹幕源选择的是“内置本机服务”还是“弹弹play 官方”；
3. 点“测试连接”后显示的**完整错误文字**（最好截图）；
4. 播放页弹幕面板里“公共弹幕”的状态文字（例如“内置弹幕服务启动失败：…”“弹幕服务请求失败（HTTP 502）”“未找到…”）；
5. 是否所有视频都不能搜到，还是只有某部作品。

这些信息能把问题锁定在：Node 启动、Node 出站网络、上游平台返回、凭证/签名、还是作品匹配。

## 5. 当前可用方案

- **现在想用弹幕**：先用“自定义 / 兼容服务”或预设（弹1 等），它们不依赖官方凭证；自定义能工作说明网络和客户端解析链路正常。
- **弹弹play 官方**：到 [开放平台](https://doc.dandanplay.com/open/) 申请应用，拿到审核通过的 AppId/AppSecret 后，在“弹幕源 → 弹弹play 开放平台”填写并点“测试连接”。
- **内置本机服务**：需要 iPhone 且安装 1.0.182+；如果测试连接仍失败，把上面的错误文字发来，我再针对 Node 侧处理。

## 6. 2026-10-22 追加：用户真机反馈（1.0.182）

用户提供的截图与诊断包：

- 设备：iOS 27.0.1，LumeBox **1.0.182**（build 182）；
- **弹弹play 开放平台审核已通过**（平台管理员留言：应用已创建并启用），截图里“测试连接”显示“连接成功，应用凭证已通过验证”；
- “内置本机服务”测试连接显示“本机服务已启动”；
- 手动匹配“大刑伺候 / 第1集”时：**能搜到作品**（`大刑伺候 2026·国产剧·tencent`），但加载提示“这部作品的该集返回 0 条弹幕”；
- 播放页公共弹幕为 0，服务标签为“内置本机服务”。

由此可以排除“官方凭证完全无效”和“内置 Node 完全没启动”：两个服务都能通过基础探测，问题落在**具体作品的搜索/剧集匹配/弹幕接口返回**。

补充验证（桌面 Node 24 + bundled danmu_api）：

- 内置服务搜索“大刑伺候”第1集返回 tencent 作品，`episodeId=10002`；
- 对该 ID 调评论接口返回 **2219 条弹幕**，说明服务代码在桌面环境能取到这一集的弹幕。

因此 iPhone 上的 0 条更可能是以下之一：
1. 设备端 Node 到具体平台评论接口的网络/风控与桌面不同；
2. 首次评论请求失败后被上游缓存为空，短时间内重复请求仍返回 0（本轮已给内置评论请求加 cache-busting 参数）；
3. 手动匹配时实际加载的不是选中的第1集（截图只看到作品卡，集数列表被截断）。

下一步需要带日志的新包验证：本轮已在弹幕客户端加入请求路径/状态码、搜索数量、评论数量的日志；装上新包后复现一次并重新导出诊断包，就能看到具体是 0 条、HTTP 错误还是选错集。

## 8. 2026-10-22 11:05 诊断包（1.0.183）追加结论

诊断包确认版本 **1.0.183**、iOS 27.0.1，日志里已有本轮的 `[danmaku]` 记录：

```
[danmaku] builtin .../api/v2/search/episodes -> 200
[danmaku] search "楚离" ep=1 -> 1
[danmaku] builtin .../api/v2/comment/10002 -> 200
[danmaku] comments 10002 -> 0
```

关键结论：

1. **内置服务本身在工作**：Node 启动、搜索接口都返回 200，搜索“楚离”找到 1 个结果；
2. **同一 episodeId=10002 在桌面上评论接口返回 2474 条，设备上返回 200 但 0 条**：问题在设备端 Node 到上游评论接口的返回，不在 Flutter 匹配代码；
3. 日志里官方服务只有 3 次 `search/episodes -> 200`，**没有实际作品搜索**记录，说明当时没有真正用官方服务打开/匹配视频（那 3 次更像“测试连接”），所以“官方不行”还需要一次真实操作验证；
4. 这进一步支持：**先关闭 VPN/代理再测内置服务**；若关闭后评论能返回，就是代理/网络出口导致上游评论接口空返回。

## 9. 弹幕面板与凭证 UI 修复

- **键盘遮挡输入框**：`DanmakuPanelFrame` 原来用屏幕高度 85% 固定高度，键盘弹出只加 padding 不缩内容，输入框会被盖住；已改为按 `LayoutBuilder` 可用高度 92% 计算，键盘弹出时面板缩小。
- **设置页填过 AppId/Secret，播放器面板还要再填**：播放器面板切换弹幕源时现在会从本机已保存的 profile 里自动带出 AppId/AppSecret；同时提示：面板显示的是“当前选中的弹幕源”，如果当前选的是“内置本机服务”，官方凭证不会显示，需要先切到官方。
- 建议删除重复的“弹弹play 开放平台”旧配置，避免选到过期凭证的那条。
