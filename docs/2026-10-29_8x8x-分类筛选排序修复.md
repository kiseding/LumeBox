# 8x8x：分类 / 筛选 / 排序补齐，播放升级为原生 HLS

2026-10-29 · `sources/video/x8x8.js`（`x8x8_video`，视频板块，18+，2.0.0 → 3.0.0）

用户反馈：8x8x 在 App 里只有「推荐」一个分类、没有筛选和排序。复测后确认站点在 10-28 改版成
「跳板域 + SPA 外壳 + 服务端渲染内容页」，旧源（只做推荐流 + webplayer）把分类/标签/详情都漏掉了。

## 一、站点形状（本次复测）

```
跳板域 1azm0i.qcsw2b5yf.com → 302 → 当前真实域（本次 113452.85hcp2.com）
真实域 /            → 347 字节外壳：<script data-body-url=/4rov3/>
真实域 /4rov3/      → 首页（含频道导航 + 12 组标签）
真实域 /4rov3/category/<1..5>/[page/N/]  → 分类页（SSR，23 张/页，共 1274 页）
真实域 /4rov3/tags/<标签>/[page/N/]      → 标签页（SSR，全站，不与频道叠加）
真实域 /4rov3/vd/<id>/                   → 详情页（SSR：标题/封面/标签 + 播放器）
真实域 /api/search/video?keyword=&page=  → 搜索（明文 JSON，28 条/页）
真实域 /json/recommend/rmd_<1..50>       → 推荐流（AES-256-GCM 密文）
```

- **根路径的 `/category/1/` 不行**：会被 SPA 兜底 302 到首页，内容页必须带 `data-body-url`
  里的前缀（`/4rov3/` 每次改版会变，源里动态取并缓存 6 小时）。
- 站点有 `/hello/` 的 localStorage 人机校验，但**只拦 SPA 外壳**；直接取内容页不需要它。

## 二、分类 / 筛选 / 排序

| 项 | 站点实情 | 源里的做法 |
|---|---|---|
| 分类 | 导航 5 个频道：大陆 / 日韩 / 欧美 / 动漫 / 三级 | `categories()` 实时抓导航（兜底内置），前面加「推荐」 |
| 筛选 | 导航 12 组标签（年龄 / 职业 / 剧情 / 吃瓜 / 身材 / 多人 / 姿势 / 反应 / 服装 / 足控 / 场景 / 特殊） | `filters()` 实时抓成 12 组；列表走 `/tags/<标签>/` |
| 排序 | **站点没有排序控件**：无 select/按钮，`?sort=`、`?order=`、`/hot/`、`/new/` 全部被忽略或 302 | 只提供两种站点真实存在的顺序：「最新」（频道/标签页的站点顺序）、「推荐」（首页推荐流） |

两个必须说清的站点限制：

1. **只认单标签**：`/tags/A+B/`、`/tags/A,B/`、`/tags/A/B/` 全部 302。组内多选时源只取第一个
   （与 `cf2` / `cf3` / `h4dh3` 的做法一致）。
2. **标签页是全站的**：没有 `category+tag` 的组合 URL，选了标签就按标签页走，不再叠加频道。

## 三、详情与播放（顺手修掉 webplayer）

详情页 SSR 里有 `#player-wrap`：

```html
data-m3u8=<hash>/m3u8/index.m3u8
data-route1=https://xn0cox.db9bmbe.com:32803/v/
data-route2=https://woyaw00.cxjaa9s8.com:1443/v/
data-route3=https://gjaorm8.z66fe6x9g.com:1443/v/
```

播放串 = `route + m3u8`。实测三条线路都 200 + `application/vnd.apple.mpegurl`，
master 里是 500kb/300kb 两个码率（分片与 key 都在同一媒体域，不需要 Referer）。

- `chapters()` 现在给「线路1/2/3」，`content()` 按线路探活，失败自动换下一条；
- 三条全挂才退回 `webplayer`（`{origin}/vd/{id}/`）；
- 详情页的标题/封面/标签（`tag-badge`，第一个是频道名）也不再依赖列表缓存。

## 四、一个 App 侧的坑

`resolveBase()` 原本靠 `reply.url` 判断跳板域 302 到了哪个真实域，但 App 的 HTTP 桥
只回报 `status / headers / body`，**没有 `url`**。旧逻辑读不到就当整站打不开（新源在真机上会直接报
「跳板域都打不开了」）。现在改为：读不到最终地址就用种子域本身——后续请求照样会被 302 带到真实域，
只是多一跳。

原生用例（快照，`snapshots/x8x8_*.html`）另外断言了：bodyRoot 解析、AES-256-GCM 推荐流解密、

## 六、限制

- 推荐流只有 50 页（站点自己限制），频道/标签页有 1274 页；
- 组内多选只生效第一个标签（站点不支持组合）；
- 「推荐」是全局推荐流，选了它就不再区分频道/标签（站点没有按频道推荐）；
- 站点会换跳板域和真实域，源里靠 302 跟随 + 30 分钟缓存，域名全换时需要更新 `SEEDS`。
