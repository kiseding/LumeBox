## 二、五个根因（这轮真正值得记的）

1. **页面域 ≠ 接口域**：Butterfly 系列的 `mirrors[0]` 是 CloudFront 静态页面域，POST 一律 405。
   凡是「登录接口在换台逻辑之外」的写法，都会把 405 直接甩给用户。
2. **App 的 QuickJS 沙箱没有 `atob` / `Buffer`**（video 类源）。任何拿它们解 base64 的脚本，
   在真机上都会静默失败 —— MatureTube 的「模板可能改版」就是这么来的（页面一直是好的）。
   纯 JS base64 解码器在本轮补上；`sources/video/citapa.js` 也有 `atob`，但它在 try/catch 里且是幂等转换，暂未动。
3. **`isAdTarget('') === true` 是放大器**：解码一失败，所有卡都被当广告。判断「未知」不能等于「广告」。
4. **渲染回来的 DOM 和原始 HTML 不一样**：`web.render` 给的是序列化后的 DOM（单引号 / `\/` 转义），
   正则解析要归一化，且解析 0 条应当换路径重试，而不是直接判「改版」。
5. **封面模板会换图床**：Iwara（帧号越界回占位图）、XTUBE（图床从 `img.doppiocdn.org` 换成
   `static-proxy.strpst.com`）、MatureTube（`ttcache`）三家各不相同 —— 封面必须逐条实测，
   不能只看「URL 拼得出来」。

## 三、复验（本机，2026-10-29，走本机代理出口）

```bash
# 分类 / 筛选是否真的换内容（首条 id 必须不同）
node tools/lume-source-check.mjs sources/video/cf3.js --call list --category ""
node tools/lume-source-check.mjs sources/video/cf3.js --call list --category 6a44e61dda79c1b7a78bb84f
node tools/lume-source-check.mjs sources/video/familyporn.js --call list --category latest --filter sort=popular
node tools/lume-source-check.mjs sources/video/maturetube.js --call list --category japanese --filter source=faphouse
node tools/lume-source-check.mjs sources/video/myfreecams.js --call list --category tag:natural

# 全量五入口
node tools/lume-source-check.mjs \
  sources/video/cf3.js sources/video/familyporn.js sources/video/maturetube.js \
  sources/video/myfreecams.js sources/video/uncams.js sources/video/twitthub.js sources/video/xtube.js
```

结果（`--call` 之外的全量跑）：Butterfly 2 / MyFreeCams / UN Cams / XTUBE 四个**全绿**；
Familyporn、MatureTube 只有 `playable` 的 mp4 探活超时（大文件走代理 20 秒内起不来流，
地址本身 200，不是源问题）；TwittHub 按预期报 Vercel 校验（本机出口 IP 一直 429，
验证后带上会话即可）。Iwara 的 `api.iwara.tv` 对 Node/undici 的 TLS 指纹回 403，
所以它用 `test/iwara_source_test.dart`（真接口夹具）复验：**All tests passed**。

`tools/lume-source-check.mjs` 本轮新增 `--category <id>` 与 `--filter <组>=<选项>`，
就是为了让源约定第 3 条（「每个分类/筛选都要真的换内容」）可以用命令行验，而不是凭截图判断。

## 四、还没解决

- **TwittHub**：Vercel 安全校验只能靠 App 的网页视图过一次（过完 App 会把会话 Cookie 注入源请求）。
  本轮只是把「吊死 8 秒再超时」改成「6 秒内给出可操作提示」，纯 HTTP 仍然过不去。
- **Familyporn 封面**：URL 实测 200（`image/jpeg`，但字节其实是 WebP —— 站点 CDN 的怪癖），
  真机空白最有可能是**图片请求没走代理**（站点直连超时）。源这边已标 `network: proxy`，
  若仍空白，需要在 App 侧确认封面请求是否与脚本请求走同一条线路。
