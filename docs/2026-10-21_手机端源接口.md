# 手机端源接口：动态网页、HTML 提取与持久存储

这些接口在手机内调用 WKWebView 与 SwiftSoup，不需要爬虫服务器。**需要重新构建包含 SwiftSoup 2.9.6 的 iOS 安装包**；旧安装包、Android 和 Windows 调用会明确提示不支持。现有 HTTP、XPath、源方法和内存缓存接口保持原行为。这里增加的是脚本可调用的能力，不会自动改写旧源。

## 读取动态网页

下面的 JavaScript 在源的异步方法中执行。网址和选择器需要由该源实际站点提供。

```javascript
async function readCards(url) {
  const page = await LumeSource.web.render({
    url,
    waitForSelector: '.card',
    timeoutMs: 6000,
    script: 'return document.querySelectorAll(".card").length;'
  });
  return await LumeSource.html.extract(page.html, {
    baseUrl: page.url,
    rowSelector: '.card',
    fields: {
      title: {selector: 'a'},
      url: {selector: 'a', attribute: 'abs:href'},
      cover: {selector: 'img', attribute: 'abs:src'}
    }
  });
}
```

`page` 返回 `status`、最终 `url`、`title`、渲染后的 `html`、自定义 `script` 的 `result` 和 `media` 列表。`script` 是异步函数体，使用 `return` 返回 JSON 可序列化的结果；不使用 `eval` 执行。

`media` 来自 DOM 中的音视频地址和资源时间线里带常见媒体扩展名的 HTTP(S) 请求，格式为 `{url, headers}`；请求头包含 UA 和 Referer。源需要从中选择正确的当前集地址，再按原来的播放内容接口返回。没有扩展名的接口、Blob/MSE 和 DRM 内容不会因此自动解析成功。登录媒体所需的其他请求头仍由源按现有播放接口提供。

## 在页面填写、点击和等待

`steps` 按顺序执行，最多 16 步：

```javascript
async function searchOnPage(url, keyword) {
  return await LumeSource.web.render({
    url,
    steps: [
      {type: 'fill', selector: '#search', value: keyword},
      {type: 'click', selector: 'button[type=submit]'},
      {type: 'wait', selector: '.search-result'}
    ]
  });
}
```

| 步骤 | 参数 | 行为 |
|---|---|---|
| `wait` | `selector` | 等元素存在；不是固定休眠 |
| `fill` | `selector`、`value` | 填写 input／textarea，触发 input 和 change 事件 |
| `click` | `selector` | 点击元素；整页导航后继续下一步 |
| `evaluate` | `script` | 执行异步 JavaScript 函数体；该步骤返回值忽略 |

首次导航默认 GET；可提供 `method: 'POST'`、字符串 `body` 和 `headers`。表单正文最大 128KB。请求会补入本源现有 HTTP 会话的 UA／请求头，WebKit 使用与内置网页相同的持久网站数据仓。用户在内置网页完成的登录可按站点复用；同一站点的 WebKit 登录态按域共享，不是每个源一份独立浏览器账号。

## 提取 HTML 字段

`LumeSource.html.extract(html, options)` 返回对象数组。`rowSelector` 省略时以整份文档为一行；未匹配到行时返回空数组。

| 字段规则 | 行为 |
|---|---|
| `selector` | 相对当前行的 CSS 选择器；省略时使用当前行元素 |
| `attribute` | 读取属性；`abs:href`／`abs:src` 按 `baseUrl` 补全地址 |
| `html: true` | 返回元素内部 HTML；默认提取文本 |
| `all: true` | 返回全部匹配值组成的数组；默认取第一项 |
| `defaultValue` | 未匹配到元素时的字符串默认值，默认为空字符串 |

每次最多 32 个字段、500 行，每个字段最多 500 项。输入 HTML 最大 2MB，输出最大 1MB；无效选择器报错。

## Python 源调用

继承 `base.spider.Spider` 的源可调用以下方法，字段和步骤规则与 JavaScript 一致：

```python
# 放在 Spider 的方法内，url 是该源的站点地址。
page = self.renderPage(url, waitForSelector='.card')
rows = self.extractHtml(page['html'], {
    'title': {'selector': 'a'},
    'url': {'selector': 'a', 'attribute': 'abs:href'},
}, rowSelector='.card', baseUrl=page['url'])
self.setItem('last_titles', [row['title'] for row in rows])
last_titles = self.getItem('last_titles', [])
```

## 保存跨重启的数据

JS：`await LumeSource.storage.set(key, value)`、`get(key, defaultValue)`、`remove(key)`。

Python：`self.setItem(key, value)`、`self.getItem(key, default)`、`self.removeItem(key)`。

值必须可转换成 JSON。数据落在所属板块的库里，按源 ID 隔离；删除键是显式操作，引擎释放不会清空。最多 64 条，单条 JSON 最多 64Ki 字符，总值最多 512Ki 字符，键最长 1024 字符。旧 `LumeSource.fs` 和 Python `getCache/setCache` 仍然是原来的内存存储。

## 验证页、频率和超时

- 网页默认预算 6 秒，最高 8 秒；还受当前脚本剩余执行预算限制。
- 源渲染同时最多 2 个，同一初始站点最多 2 个；与旧网页回读共用最多 3 个受管 WebKit 会话；队列忙时明确报错。
- 页面 HTML 最大 512KB，包含自定义结果的完整响应最大 768KB。
- 识别到 Cloudflare 验证页时返回 `NEED_WEBVIEW_VERIFY`，接入现有网页验证流程。验证码和登录仍由用户完成，不假装成空内容。
- HTTP 429 提示稍后重试，401／403 提示检查登录／访问权限。HTTP 队列对 429、500、502、503、504 及临时连接失败执行按域名退避。
- 源释放、超时或网页进程退出时，取消该请求并拒绝迟到结果。

## 统一会话与系统网络

iOS 源 HTTP 请求统一经系统 URLSession，WKWebView 跟随同一系统代理／VPN；不新增代理隧道。其他平台仍沿用原网络设置。第三方播放器内核的网络实现由内核提供，VPN 是整体统一路由的方式，不能把 URLSession 的系统 HTTP 代理行为泛化为所有第三方内核都支持 PAC。

Cookie 从系统 WebKit 仓库按域名、路径、Secure、有效期取用；HTTP 的 Set-Cookie 会回写 WebKit。每站点可选择 UA：设置 → 网络设置 → 按站点设置 UA。更换 UA 会清掉该站旧的 Cloudflare 绑定凭证，以免沿用与新 UA 不匹配的校验。请求优先保留脚本提供的 Referer；缺少时播放地址绑定源页面地址，HTTPS 降级到 HTTP 时不转发页面 Referer。

JS 可在源异步方法中调用 `await LumeSource.session.setUserAgent(url, ua)`；Python 可调用 `lume_tools.set_user_agent(url, ua)`。按站点 UA 是应用会话偏好，同站点多个源共享。它不代表按源独立浏览器账号。

301/302 的 POST 会改为 GET，303 除 HEAD 外改为 GET，307/308 保持方法和正文。相对 Location 会补全，最多跟随 10 次，检测循环，只允许 HTTP(S)。跨 origin 移除 Cookie、Authorization、Proxy-Authorization 和 Host，再选择目标站自己的会话。

## 网页拦截、等待与验证

`web.render` 增加以下选项：

| 参数 | 默认与范围 |
|---|---|
| `pageTimeoutMs` | 页面加载预算，默认当前总预算 |
| `elementTimeoutMs` | 单次元素等待预算，默认当前总预算 |
| `apiTimeoutMs` | 网页辅助接口的请求预算，默认当前总预算 |
| `timeoutMs` | 总预算默认 6000ms，最高 8000ms，还受脚本预算限制 |
| `blockAds` | 默认 true；仅屏蔽列出的第三方广告／埋点域名 |
| `blockImages` | 默认 false，开启时过滤图片；进入人工验证时撤销过滤 |

三种分阶段预算均受总预算约束。页面开始加载前注入 `LumeWeb.css(selector)`、`LumeWeb.xpath(expression)`、`LumeWeb.request(url, options)`。前两项返回节点数组；request 返回 fetch Response，超时抛出 `API_TIMEOUT`，遵守当前页的 CORS、CSP 和权限。

返回 `requests`：最多 16 条 XHR／fetch 的 URL、状态、类型、受限正文摘要。fetch 只读取非 opaque 且声明长度不超过 16KiB 的文本／JSON 副本；不主动读取大型流媒体响应，不绕过跨域规则。

遇到明确验证页保留原 WebView 最多 180 秒，交给原有网页验证入口显示。成功后同步 Cookie／UA，清除失效链接标记，再由原有流程重试源调用；取消、超时或进程终止均释放页面。手动验证仍需用户完成。

错误包括 `verification`、`ip_blocked`（仅站点明确提示封禁时）、`http_401`、`http_403`、`rate_limited`、`page_timeout`、`element_not_found`、`api_timeout`、`total_timeout`、`navigation`、`javascript`、`terminated`。不把所有 403 都推断为封 IP 或验证码。

受管页面完成后销毁文档、脚本和规则；后台页面受共享并发预算限制。空闲时最多每 5 分钟清理 WebKit 磁盘／内存缓存，内存警告时取消后台任务并立即清缓存。Cookie 与登录所需 localStorage 保留，删除源并清理站点数据时按域名清除。

## 通用工具

所有 JS 源都可调用同步 `pako.inflate(bytes, {to:'string'})`，内置固定版本 pako 2.1.0（MIT），随安装包提供，不在线下载脚本。其分配受 QuickJS 的内存和执行预算限制。

`LumeSource.tools` 的 digest、aes、rsa、inflate、base64Encode、base64Decode、urlEncode、urlDecode 均为异步宿主调用。二进制输入／输出使用 base64；字符串使用 UTF-8。

```javascript
async function sourceToolsExample() {
  const digest = await LumeSource.tools.digest('sha512', 'LumeBox');
  const encoded = await LumeSource.tools.base64Encode('中文');
  const decoded = await LumeSource.tools.base64Decode(encoded);
  return {digest, decoded};
}
```

AES 参数：`{encrypt, mode:'CBC'|'ECB', key, iv, data, padding:'none'}`，key、iv、data 为 base64；不传 padding 使用 PKCS7。CBC IV 为 16 字节，AES key 为 16/24/32 字节。RSA 参数：`{encrypt, pem, data}`，支持 PEM 的 PKCS1／SPKI／PKCS8，RSA PKCS#1 v1.5 编解码，1024–4096 位，单块长度受密钥限制。摘要支持 MD5、SHA1、SHA224、SHA256、SHA384、SHA512。宿主 inflate 支持 zlib/gzip 和 raw DEFLATE，解压输出最多 8MB。

Python 用 `import lume_tools`：`digest(algorithm, data)`、`aes(**options)`、`rsa(**options)`、`inflate(bytes, raw=False)`、`base64_encode/decode`、`url_encode/decode`。原有 Crypto、hashlib、base64、urllib.parse、zlib 接口继续保留。

## 媒体模块与分片

JS：`await LumeSource.media.parseM3u8(text,url)`、`playlist(url,options)`、`segment(url,index,options)`、`inspectFlv(base64Data)`。options 可含 headers、referer。Python：`lume_tools.media(operation, **options)`，operation 同名。

- M3U8 解析标准 AES-128/identity、NONE、密钥切换、相对 URI、MEDIA-SEQUENCE、显式／默认 IV、BYTERANGE、EXT-X-MAP 和主清单线路。
- `segment` 接受**媒体清单 URL**和从 0 开始的 index，自动取得 16 字节密钥并进行 AES-CBC/PKCS7 解密，返回 `{data,segment}`，data 为 base64。主清单请先选择其中一条媒体清单。
- 每个媒体运行时最多缓存 8 枚密钥，5 分钟过期，按地址、密钥声明位置和请求头身份隔离；引擎释放时清空。分片最大 16MB，遵守 Range，失败走共享重试队列。初始化段元信息在解析结果中返回，不把单个分片伪装成完整可播放文件。
- 播放器照常将标准 HLS/AES 交给原有内核处理；MPV／MDK 增加 FFmpeg 的 HTTP 重连和 HLS 分片重试参数，AVPlayer 在明确的临时网络错误时最多 3 次按 1/2/4 秒重开并恢复进度。永久错误、解密失败、403 不盲目重试。不同内核版本对底层选项支持仍需设备验收。
- FLV 模块检查文件头、tag 长度、时间戳与音视频编码标记；解复用、解码与渲染仍由支持 FLV 的内核负责，不表示 AVPlayer 新增了 FLV 解码器。
- DRM／SAMPLE-AES 不由此模块解密，保留平台权限和内容保护边界。

## 编码、失效链接与诊断

Dart 保留原始响应字节，文本按 HTTP charset、HTML meta、BOM 判断；iOS 用系统编码库处理 GBK／GB2312／GB18030，UTF-16 BOM 也可识别。Python requests 原有编码接口保留。

幂等请求重试；POST 不自动重试。按域名计数／退避时释放全局额度，尊重 Retry-After（最多 30 秒）。GET 的 404 缓存 60 秒、410 缓存 300 秒，最多 256 条，按 URL、方法、请求头身份隔离；不缓存 403、验证码或 5xx。设置 → 网络设置可清除标记，验证成功后也会清除。

设置 → 网络设置 → Safari 远程网页调试，默认关闭。iOS 16.4 起仅在用户开启后启用 `isInspectable`，可用连接的 Mac Safari 开发菜单检查网页。原生检查工作流 `Check source runtime (no IPA)` 只编译模块、检查 XCTest 类型，不生成 App／IPA；它不是已运行全部 iOS 真机测试的声明。

补充的运行时保护：QuickJS 原生内存不足标记可区分真正 OOM 与普通 `throw null`，内存耗尽后回收并重建源上下文，原有配额不放宽。

参考：[Apple WebKit 数据仓](https://developer.apple.com/documentation/webkit/wkwebsitedatastore)、[WebKit 调试开关](https://webkit.org/blog/13936/enabling-the-inspection-of-web-content-in-apps/)、[HLS 标准 AES-128](https://www.rfc-editor.org/rfc/rfc8216)、[FFmpeg HTTP 重连](https://ffmpeg.org/ffmpeg-protocols.html)、[pako 2.1.0](https://github.com/nodeca/pako/tree/2.1.0)。

## 取色、AI 超分与 TMDB 的隔离

“字体与字号”已从全局显示设置移除。自适应颜色仅作用于当前首页的局部主题，不把封面色写入用户主题配置；TMDB 的资料缓存与匹配状态独立，关闭或修改配置后的旧结果会被代数检查丢弃，不更改播放地址。

修复了取色触发自动超分的性能交叉：`SectionImagePipeline.colorSample` 从同一会话的原始图片字节生成至多 64×64 的采样位图，不调用 `decodeTransform`、不占展示位图缓存，使用后直接释放。它仍复用原图下载和磁盘缓存。自动超分的封面与阅读器任务共用一个设备并发预算（默认 1、最高 4），等待队列超过 32 时保留原图，避免快速滑动积压大量待增强图片。TMDB 网络与 AI 推理仍会消耗设备资源；这里消除了上述重复处理路径，不承诺任何设备上完全零开销。

## 请求取消、版本恢复、体检和断网恢复

### 怎样使用

- **源体检**：打开对应版块的「源管理」→ 顶部「…」→「一键源体检」→ 选择一个源。逐项显示运行环境、分类、首页（若提供）、分类列表、封面、详情、目录及正文／播放地址的结果，并给出处理建议。退出页面或点「停止」结束本次检查。
- **恢复上一版**：在同一菜单点「恢复上一版源」，选择源，核对当前和上一版的版本号，再点「恢复」。账号、网络配置、站点设置、分组、启用状态、书架和进度保留；恢复后重新打开源或体检。每个源仅保留最近一次脚本变更之前的一份，首次安装或启用此功能之前的更新没有历史备份。版本号相同而脚本内容不同也会保存。
- **断网恢复**：不需要额外开关。iOS 源 HTTP 请求由 URLSession 等待系统连接；等待时页面提示「正在等待网络，恢复后继续…」。恢复 Wi-Fi／蜂窝网络后，在剩余预算内继续。切换中已断开的连接按现有幂等重试规则处理。超时后仍可手动重试。
- **重复请求与退出取消**：无需配置。相同身份的在途 GET／HEAD 共用一次下载；快速切换源、替换搜索、翻章及离开页面时撤销相应请求。正在播放的内核有独立生命周期，页面取消不会关闭共享源引擎或其他页面仍在使用的下载。

### 实现与范围

共享请求按 URL、方法、源标识、Cookie／UA／Referer 等全部请求头、超时、读取上限和网络选项隔离，只合并没有请求体的 GET／HEAD。它不是响应缓存；完成后再次请求仍会读取网络。POST 不合并。每个消费者独立取消，最后一个消费者退出后才中断物理请求；排队和退避等待也可取消。单次尝试与整个请求都有上限，超时会停止该次传输，不让旧连接在重试期间继续占用资源。

QuickJS 与 Python 的宿主网络调用传递调用方的页面生命周期；Python 按源串行排队以免宿主回调错误关联到另一次调用。网页渲染、系统 HTTP 和备用 WebKit 读取都有原生取消通路。封面管线释放时停止其请求。共享预热、源运行环境初始化和已经交给播放器的任务按自己的生命周期管理；内嵌 Node 服务内部自行发出的上游任务仍受该服务原有超时控制，不能将取消本地 HTTP 连接等同于杀死 Node 内的所有任务。

源更新在同一 SQLite 事务内保存上一版及写入新脚本。恢复时重新验证旧脚本，恢复脚本与记录被拒绝版本的 SHA-256 在同一事务完成；后续订阅刷新拒绝再次安装完全相同的已回滚脚本，作者发布不同内容的版本后可以正常更新。保存的是上一次通过导入校验的脚本，不承诺旧网站仍然在线。备份随源删除而清除，不进入源导出文件。

体检总预算 40 秒；最多尝试两个分类、读取一张封面前 32KB（8 秒），不整章下载、不实际起播。HTTP 403、验证码、缺依赖、解析失败等分开说明；封面错误不妨碍继续检查详情。图片探测会排除空数据、HTML／JSON 错误响应，但不是完整图片解码或视频播放验收。错误显示去除 URL 查询参数、账号信息及常见凭据字段。

iOS 使用一个系统网络观察器及 `waitsForConnectivity`，不探测第三方地址、不建立 App 内代理隧道。等待状态按请求分别清理，迟到回调不能重新显示已经结束的等待提示。受单次请求、队列总预算和源脚本执行预算共同限制，不会无限等待。

## 21:00 播放、登录与导航反馈

### 弹幕与三个内核

- 内联 Flutter 弹幕共用 PlaybackClock：根据单调帧时间平滑推进，分别覆盖 200／400／500ms 进度采样和 0.5／1／2 倍速。迟到的小幅进度回报不清空已有弹幕，横向滚动保留亚像素位置；暂停、跳转与停报位置有界处理。
- MPV、MDK 画中画帧泵采用同一平滑时钟提交时间戳；AVPlayer 保留原生 VideoOutput 取帧路径，不通过 Dart 截图。开启画中画弹幕时会使用合成帧，关闭时仍可直接绑定 AVPlayerLayer。
- AVPlayer 开启允许后台持续视频输出的策略；帧显示层绑定媒体时基，播放、暂停、倍速一并同步。进入窗口的过渡状态保持播放，0.5 倍速也不会被系统播放按钮强制改成 1 倍速。旋转元数据只在附加内容源时读取，避免每帧同步访问资源轨道。
- 原生画中画弹幕改为逐条进入并保留轨道，退出后回收；不会每帧重算最近八秒导致同一条弹幕换行。文字排版缓存继续复用。
- 三个内核均有页面级“不重建内核、进入时主动播放、处理后台切换”回归。它们使用替身内核，不能代替 iPhone 上真实解码、系统窗口、后台音视频及帧率验收。

官方弹弹play搜索先调用带 v2=true 的剧集搜索；没有精确片名时，再查询官方 TMDB 作品并读取剧集信息。只补充精确片名，仍需用户核对作品、年份、集数并成功读取非空评论；连接测试只检验一次接口鉴权，不表示库里一定有当前电视剧。依据：[官方 OpenAPI](https://api.dandanplay.net/swagger/v2/swagger.json)。没有使用用户应用密钥进行在线节目命中验收。
