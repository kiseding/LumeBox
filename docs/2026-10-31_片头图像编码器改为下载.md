# 片头图像编码器改为下载

2026-10-31。承接 [离线音色包改为在线下载](2026-10-31_离线音色包改为在线下载.md)，处理包里第二块的「数据类」资产。

## 结论

`mobileclip_s0_image.zip`（20.18 MiB）不再随包，首次启用「片头片尾识别」时下载并校验。

| 位置 | 变化 |
|---|---|
| 未签名 IPA | −20.18 MiB |
| 仓库 | +20.18 MiB（git 历史永久增加） |
| 首次开启片头识别 | 下载 20 MB + YAMNet 15 MB |

## 为什么不能像音色包那样直接指向上游

音色包能用 Hugging Face，是因为上游就托管着同一份文件。这个不行：它是我们自己用
`tool/prepare_intro_models.py` 把 MobileCLIP-S0 转成 Core ML 之后的产物，网上没有同款；
上游 `apple/MobileCLIP-S0` 只有 PyTorch 权重（94.73 MiB，就是仓库里的
`assets/models/intro/mobileclip_s0.zip`），而手机上没法做 Core ML 转换。

所以只能自己托管。现在放在仓库里：`assets/models/intro/mobileclip_s0_image.zip`，
运行时用 GitHub contents API 的 raw 形式下载（jsDelivr 单文件上限 20 MB，这个刚好超一点，
会退回到 GitHub）。台账上它是仓库 +20 MB 换 IPA −20 MB；git 历史一旦提交就再也删不掉，
这一点和音色包不同，需要知悉。

## 实现

- `lib/core/intro/intro_backend.dart`：`_installVideo()` 里原来 `rootBundle.load`
  改成 `ModelSource.fetch(..., digest: _imagePackSha256)`，落盘仍是
  `ApplicationSupport/reference_intro_models_3e0a7bfb/models.zip`，后面解压、
  清理旧文本编码器的步骤一字未改。
- `_imagePackSha256 = 30c22892…`，与 build 期 `tool/prepare_intro_models.py` 写出的
  `compact_checksums.json` 同值（取自 2026-10-30 那次构建产物，已比对）。
- `pubspec.yaml` 移除该资产；`.gitignore` 取消对它的忽略，否则「提交了却不被跟踪」。
- 文案：设置页不再说「内置」，首次准备会提示需要下载多少。

## 注意

`tool/prepare_intro_models.py` 每次构建仍会重新生成这个 zip（不从仓库读）。生成物的
zip 内嵌时间戳，字节可能与提交版不同——不影响：它既不进包、也不作为下载源，
下载源固定是仓库里这一份，摘要也钉死了。
