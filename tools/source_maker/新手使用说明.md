# LumeBox 制源工坊 0.5 新手使用说明

适用文件：LumeBox-SourceMaker-0.5.exe，Windows x64。

这份说明按界面实际按钮编写。第一次先看第 1～4 部分，成功做出一个源后，再使用批量和高级功能。

## 1. 先弄懂工具做什么

工具分两步工作：先从网站找到作品、标题、封面、章节和内容，再把这些规则转换为 LumeBox 可以运行的源文件。以后 App 使用这个源时，会重新访问网站，不依赖这台电脑一直开机。

“预览有标题”只能证明找到了一些链接。分类页、作者介绍页也有标题，它们未必是可播放、可阅读的作品。因此要经过“生成源 → 验证源 → 导出源”。

当前优先使用 JS。普通视频的 JS 检查失败后，会尝试静态 PY 备用方案；浏览器模式不自动降为静态 PY。漫画目前使用 JS，漫画 PY 仍需要 App 进一步支持。

需要手动完成验证的网站，Windows 与手机是两个独立的环境。电脑验证成功，不代表手机也已经验证。工具不会把电脑 Cookie 放进源文件。

## 2. 第一次：先做一个普通视频或漫画源

1. 打开 `LumeBox-SourceMaker-0.5.exe`。
2. 在最上面输入网站的作品列表网址。优先使用能看到一排排视频或漫画封面的页面。
3. 在网址右边选择“视频”或“漫画”。先不要选 PY、猫源、Kazumi 等格式。
4. 引擎先保持“内置浏览器”，点击“开始识别”。这个快速识别步骤先使用普通网络请求。
5. 看左侧“抓取预览”：应该是具体作品，不应主要是登录、作者、人物、关于我们等导航链接。
6. 看右侧“源名称”，默认使用网站完整标题，可以改为自己容易识别的名字。“源 ID”一般保持默认。
7. 点击底部“生成源”。弹出的窗口展示生成的代码草稿；不需要看懂代码，点击“返回验证”。
8. 点击“验证源”。工具最多抽查 3 个作品的详情、章节和内容，并检查已适配的分类与筛选请求。
9. 验证通过后，“导出源”才能点击。保存文件，记住保存目录。
10. 把导出的文件传到手机，在 App 对应模块的源管理中导入，切换到该源，实际打开作品并播放或阅读。

验证成功不等于每个作品都正常。工具检查媒体地址，但不会替你实际播放整个视频，也不会逐张下载检查所有漫画图片。

如果第 4 步提示没有识别到内容、需要验证或页面动态加载，按下一部分操作。

## 3. 网站需要验证、登录或动态加载时

“静态页面”可以理解为：普通请求就能拿到作品信息。“动态页面”可以理解为：浏览器运行网页里的程序后，作品才出现。小白不需要先判断是哪一种，普通识别失败后尝试浏览器即可。

建议顺序：普通识别 → Playwright → Scrapling 浏览器会话 → Selenium。它们没有固定的强弱排名，某个网站在其中一种环境里更正常，就用那一种。

具体操作：

1. 在引擎选择框选“Playwright”。
2. 点击“连接所选引擎”。
3. 在打开的浏览器中手动完成登录或验证。
4. 等真正的作品列表和封面出现；只看到验证成功字样时，可以再等页面跳转完成。
5. 返回制源工具，点击“已验证，继续”。不要把这个按钮当成自动填写验证码的按钮。
6. 工具继续识别，得到候选作品后再生成、验证和导出。

Playwright、Selenium 和内置浏览器需要保留会话窗口。Scrapling 的抓取页返回数据后可能关闭，这是其抓取方式；选择带“会话”的模式可以在该工作进程内保留状态。

想换一个站点：先点“结束浏览器会话”，修改网址，再连接。已有会话只用于原站点，遇到跨站跳转或跨域接口可能需要单独适配。

电脑验证完以后，手机打开源仍要求验证：到 App 提供的网页视图中再手动完成一次，之后返回重试。

## 4. 如何选择引擎

| 界面选项 | 用途 | 新手建议 |
| --- | --- | --- |
| 内置浏览器 | 连接后使用 WebView2；直接“开始识别”先尝试普通请求 | 第一次保持默认即可 |
| Playwright | 浏览器加载、手动验证、页面操作、JSON 接口记录 | 动态网页优先试它 |
| Selenium | 另一种浏览器控制方式，支持相同的常用制源操作 | Playwright 不适合该网站时尝试 |
| Scrapling HTTP | 使用 Fetcher 普通 HTTP 抓取 | 页面信息直接存在于 HTML 时使用 |
| Scrapling 异步 HTTP | 使用 AsyncFetcher 的异步请求接口 | 可作为 HTTP 兼容选项；单个网站不一定更快 |
| Scrapling HTTP 会话 | 在多次 HTTP 请求之间保留 Cookie 等状态 | 连续访问相关页面时使用 |
| Scrapling 异步 HTTP 会话 | 异步 HTTP 加会话状态 | 功能类似上面，内部执行方式不同 |
| Scrapling 浏览器 | 单次浏览器抓取，使用 StealthyFetcher | 动态网页的另一种选择 |
| Scrapling 异步浏览器 | 使用异步浏览器抓取接口 | 与上面用途类似 |
| Scrapling 浏览器会话 | 使用 StealthySession，保留浏览器状态 | Scrapling 中优先试此模式 |
| Scrapling 异步浏览器会话 | 使用 AsyncStealthySession | 同样适合连续抓取相关页面 |

HTTP 模式不能靠等待把网页里的程序运行出来；动态页面要用浏览器模式。名称里的“异步”也不代表一定能突破验证，或一定比其他模式更快。

Scrapling 0.5 已不再单列旧教程中的 DynamicFetcher。当前工具使用 0.5 的抓取与会话接口，自动验证码处理未启用。

运行环境：浏览器功能使用本机 Edge / WebView2。Selenium 首次使用可能联网取得匹配的驱动。便携 EXE 已包含 Python 和工具依赖，不需要你自己安装 Python。

## 5. 每个主要按钮做什么

| 按钮 | 什么时候使用 |
| --- | --- |
| 开始识别 | 根据输入网址和模块识别候选作品；选了其他引擎且未连接时，会启动相应连接流程 |
| 连接所选引擎 | 启动当前选择的 HTTP 或浏览器引擎；换引擎时点这里 |
| 已验证，继续 | 浏览器里已手动完成验证后，允许工具继续采集 |
| 结束浏览器会话 | 换站点、结束当前采集或准备重新登录时使用 |
| 重新预览 | 修改列表或解析规则后，重新检查候选作品 |
| 生成源 | 生成 App 格式的源代码草稿；还不代表能用 |
| 验证源 | 抽查作品链路；失败时不允许作为可用源导出 |
| 导出源 | 保存通过验证的源文件，之后传到手机导入 |
| 保存工程 | 保存网址和解析设置，方便下次继续修改；工程本身不是可导入的源 |
| 打开工程 | 读取保存过的工程，需要重新预览和验证 |
| 暂停批量 | 暂停当前批量任务的后续处理，正在进行的请求需要等待返回 |
| 查看各引擎功能范围 | 查看这版真正接入了哪些能力以及限制 |

网址、规则或浏览器操作改变后，旧验证结果会失效，需要重新生成和验证。这是正常行为。

## 6. 各模块与文件如何导入 App

| 你要制作的内容 / 格式 | 工具里选择 | 导出文件 | App 导入位置 |
| --- | --- | --- | --- |
| 视频 | 视频 | 通常 `.js`；普通静态视频可能自动尝试 `.py` | 视频源管理；JS 走普通源，PY 走 PY 入口 |
| 漫画 | 漫画 | `.js` | 漫画板块的源管理 |
| 图片、图集 | 图片 | `.js` | 漫画板块；之后可分到“美图” |
| 有声小说 | 有声小说 | `.js` | 对应有声小说源入口；底层使用音频内容模型 |
| 直接制作 Python 视频源 | PY | `.py` | 视频源选择 → PY → 导入文件 |
| 模块格式 | 模块 | `.cjs` | 视频源选择 → 模块 → 导入文件 |
| Node 猫源 | 猫源 | `.zip` | 视频源选择 → 猫源 → 猫源订阅 → 导入本地 ZIP |
| Kazumi 规则 | Kazumi | `.json` | 视频源选择 → Kazumi → 导入规则 JSON |
| 网页导航 | 网页 | `.html` | 视频源选择 → 网页 → 导入 HTML 文件 |

新手通常只需要“视频”“漫画”“有声小说”，不必为了“更强”去换格式。换格式不会自动解决错误的作品规则或专用播放器。

网页模式输出的是抓取时的链接导航快照，不是完整视频播放源。保存工程生成的 `.project.json` 也不要当作 Kazumi 源导入。

浏览器会话源目前使用 JS 或模块；PY 和猫源暂不支持此浏览器模式。Kazumi 的 HTML 规则需要真实搜索地址及对应 XPath，初次使用先做普通 JS。

## 7. 自动适应：网站改版后怎么用

“Scrapling 改版自动适应 · 验证通过后学习”默认勾选，建议保持开启。

它的流程是：第一次验证通过 → 工具记住列表卡片、章节和图片区域的结构 → 以后重新识别同一入口 → 尝试定位变化后的元素 → 生成新规则并重新验证。

例如原来的网站用一种卡片样式，改版后换了类名，但内容结构仍然相近，工具可能恢复出新的 CSS。改版过大、内容消失或匹配不可靠时，也可能恢复失败，不会保证全部网站自动修好。

需要重新学习时：输入原来的入口网址，点“忘记本站样本”，再重新识别、验证。样本保存在电脑本地。

重要：这个功能用于 Windows 制源过程。你之前已导入手机的 JS 不会自行下载 Scrapling，也不会自动获得电脑的新规则。恢复成功后要重新导出，并在手机中更新源。

## 8. 点击加载更多、滚动和等待怎么设置

大多数网站第一次不需要改。只有预览作品太少、页面需要点“加载更多”，或滚动到底部才出现作品时，再打开“浏览器操作 / 接口记录”。这些操作只在浏览器模式执行。

| 设置 | 含义 | 新手如何处理 |
| --- | --- | --- |
| 加载更多按钮 CSS | 告诉工具要点击网页中的哪个按钮 | 不知道规则时留空，不要随便填写 |
| 点击次数 | 每页点击按钮的次数，0～3 次 | 没有加载更多时为 0；先试 1 |
| 滚动次数 | 向页面底部滚动，0～3 次 | 懒加载页面先试 1～2 |
| 操作后等待出现的 CSS | 等作品区域出现后再取页面 | 不知道规则时留空 |

CSS 是“定位网页某个区域的地址”，它必须对应当前网站。假设开发者确认网页按钮的 ID 就是 `loadMore`，规则才会写为 `#loadMore`。这只是说明写法，不表示每个网站都能照抄。

填写后点“保存操作”，重新预览、生成、验证。操作设置会保存到工程，也会写进动态 JS，让 App 使用同一套加载步骤。

App 的页面调用有时间限制，因此不能无限点击或一直滚动。复杂长流程仍可能需要专门适配。工具会拒绝用此功能提交普通表单，不要把付款、留言、提交资料等按钮设成“加载更多”。

## 9. “读取接口响应”有什么用

有些网页先请求后台数据，再把数据画成封面列表。接口记录可以帮助适配人员找到真正的数据地址。

1. 连接 Playwright、Selenium 或 Scrapling 浏览器。
2. 让工具打开和采集目标页面；需要时按上一节配置加载更多。
3. 打开“浏览器操作 / 接口记录”。
4. 点击“读取接口响应（不含请求头）”。
5. 回到主界面左下方日志查看结果。

工具最多保留最近 20 条同站 JSON 响应，每条最多 256KB，并隐藏常见 Token、密码等字段。内置浏览器不提供此接口响应记录。

没有记录不一定代表网页没有数据：它也可能使用 HTML、其他域名、其他返回格式或不在记录范围内。

这项功能帮助定位接口，不会把看到的任意接口自动认定为可播放源。小白遇到难站时，可提供工程文件和错误日志，请适配人员继续处理，不需要自己看懂 JSON。

## 10. 批量制源：多个网站一起做

批量入口叫“批量制源 · Scrapy”。Scrapy 和 Scrapling 是两个不同的工具。

1. 主界面先选好要制作的模块，例如“视频”。一次批量任务按这个模块处理。
2. 点击“批量制源 · Scrapy”。
3. 每行填写一个公开列表网址，一次 1～10 个。
4. 并发保持 2、间隔保持 0.5 秒、失败重试保持 1，先用默认值。
5. 点击“选择目录并开始”，最好为这批任务选择一个单独的文件夹。
6. 在主界面日志里看下载、识别和验证进度。
7. 结束后打开所选文件夹，里面只有通过验证的源，以及任务和诊断文件。

并发指同时处理多少请求；间隔是请求之间留多长时间；失败重试指失败后再尝试几次。并发最高不代表成功率最高。工具启用自动限速并遵守网站 robots 规则。

想中断：点击主界面的“暂停批量”。再次做同一批时，使用相同的网址、相同模块和同一个目录，工具会核对已经导出的文件，完整结果可以复用，未完成或失败的继续处理。

输出目录中的 `制源任务.json` 是续作检查点，`采集诊断.json` 是结果报告，两个文件都不是 App 源。不要改名或删除任务文件后再期待自动续作。

批量适合无需登录、无需人工验证的公开页面。需要验证的站点，回主界面单独处理。

## 11. 右侧设置什么时候需要改

| 设置 | 用途 | 建议 |
| --- | --- | --- |
| 源名称 | App 中显示的名字，也是导出文件名的依据 | 可以改；默认网站标题 |
| 源 ID | 区分源的固定编号 | 保持默认 |
| 列表网址 | 作品列表页面 | 应该能看到多部作品 |
| 搜索网址 | 真正的站内搜索地址 | 工具没识别到时先留空，需适配才填写 |
| 列表链接规则 | 筛出作品链接的正则规则 | 不懂时先不改 |
| 分类链接规则 | 找到分类入口 | 识别不到时需要具体网站规则 |
| 章节 / 选集链接规则 | 找到每一集、每一话的链接 | 作品页与分类页不同，不能任意替换 |
| 漫画 / 图片内容元素 ID | 限定正文图片区域，排除广告 | 知道真实 ID 才填，不带 `#` |

列表分页里 `{page}` 表示页码，搜索里的 `{keyword}` 表示搜索词。只有确认网站地址本来就这样变化时，才把相应部分换成占位符。工具也会尝试使用网页真实的“下一页”链接。

“高级解析规则 · CSS”可单独设置列表卡片、作品链接、标题、封面、章节、漫画图片和下一页。“编辑 Kazumi XPath”只给 Kazumi 规则使用。两者都属于进阶适配，初次使用不要乱填。

没有识别到分类和筛选时，工具会报告“未适配”或只显示“全部”。即使最终能播放，也不代表分类、搜索、筛选全部已经支持。

## 12. 常见问题与下一步

| 现象 / 报错 | 含义 | 怎么处理 |
| --- | --- | --- |
| 没有识别到内容链接 | 网址可能是空壳动态页、导航页或规则不适合 | 换具体列表页；再试浏览器引擎 |
| 需要人工验证、HTTP 403 / 503 | 网站要求验证、登录、限流或暂时不可用 | 用浏览器手动完成；仍失败时稍后重试或适配 |
| 选集样本失败，可能是导航、人物或分类页 | 候选链接不是作品，或章节规则没找到正确内容 | 检查左侧链接，换列表入口或修正作品、章节规则；不要强行导出 |
| 未找到公开媒体直链 | 页面能打开，但工具没有取到实际音视频地址 | 换引擎未必能解决，需要检查播放器或后台接口 |
| 没有分类、筛选 | 对应规则尚未适配，或者接口本来没有这些数据 | 查看日志，提供工程继续适配；不要虚构筛选项 |
| 封面是占位图 | 封面地址缺失，或图片请求条件不符合 | 检查封面规则、懒加载字段与 App 图片请求 |
| 源名称变了 | 默认采用网站完整标题 | 右侧“源名称”手动修改，再生成验证 |
| 导出按钮灰色 | 未生成、未验证或设置改变使旧结果失效 | 重新生成并验证，查看错误日志 |
| 浏览器会话已关闭 | 原验证窗口或工作进程已结束 | 重新连接所选引擎、手动验证 |
| 电脑正常、手机失败 | 两边会话和运行环境不同，也可能是手机超时或图片/媒体限制 | 手机再验证；保存 App 诊断，检查具体失败阶段 |
| 源能导入，但播放失败 | 导入格式正确，实际内容链路仍存在问题 | 提供该作品、源文件和 App 诊断，继续排查 |

遇到问题时，建议一起提供：网站列表网址、工具版本、选用引擎、选择的模块、错误日志、“保存工程”产生的文件；已经导入 App 的，再提供导出的源和 App 诊断包。不要发送账号密码或私人 Cookie。

当前工具覆盖的是制源工作流，并没有把所有 SDK 接口做成图形化编辑器。分布式集群、远程爬虫部署、MCP 服务、任意专用加密播放器等没有接入。实际可用范围以界面功能、验证日志和手机测试结果为准。
