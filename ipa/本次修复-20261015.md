## 1. 源图标好多都没有

根因（2026-10-15 实测）：直接按 `${站点}/favicon.ico` 取图标这条路本身是错的——

| 站点 | `/favicon.ico` 实际返回 | 真图标位置 |
| --- | --- | --- |
| JComic | HTTP 200 + **HTML**（站点的 404 页） | 首页没有 `rel=icon`，暂时只能显示首字母 |
| 18禁漫 / NN韩漫 / 色友 / X漫 | 404 | 首页 `<link rel=icon>` |
| HANMAN18 | 404 | 首页 `/fav.png` |
| 巴卡漫画 | 403（Cloudflare） | 需要源站会话 |

新增 `lib/core/source/source_favicon.dart`，取图标顺序改为：
源脚本声明的 `icon` → `/favicon.ico` → `/favicon.png` → `/apple-touch-icon.png`
→ 全都不行才抓**首页**解析 `<link rel=icon>`（apple-touch-icon 优先、按 `sizes` 从大到小、跳过 SVG）。
并且：

- 请求走**全局网络队列**（与其它请求共用并发额度），带上该源**验证过的会话**
  （Cookie + 验证时的 UA）——但只发给源站自己的域名（`SourceRequestLog.ownsHost`）；
  一个候选都连不上时不再去抓首页，直接回退首字母，列表不跟着拖；
- 校验内容**真的是图片**（content-type + 字节魔数）：HTML 404 页、SVG、空响应都当「没有」；
- 按源缓存结果（含失败），列表滚动 / 切页签不再重复打同一个站。

本机 2026-10-15 直连实测：楠楠漫画 17203B、P5 9662B、MM-CG 318B、三四漫画 3241B、
X漫 5639B 都取到了真图标；18comic.vip / 漫蛙在本机网络下不通（NONE）。

## 1. 播放请求头被整份丢掉（Hanime1 的根因）

日志原文：`[player] 播放失败：... 已取消加载｜地址域名 hanime1.me｜请求头 无`。

- `SourcePlayback.contentHeaders` 写的是 `highestQuality(content)?.headers ?? content.headers`
  —— **空的 Map 不是 null**，于是「带 qualities 的图源」（Hanime1 / H動漫網 / 瓜子影视这类
  把线路写成 `{label,url}` 的）请求头被整份丢掉：Referer、UA 一个都没交给内核，
  请求裸奔到 CDN，回来的就是 CF 挑战页（AVPlayer 报
  `-12939 byte range and no content length - error code is 200`）。
- 改成与逐线路同一套继承规则（线路自己写了就用它的，没写就继承主 headers）。
- 顺带：媒体地址就在**源站自己域名**上时，网页验证拿到的会话 Cookie（`cf_clearance`）也一起带上
  （只发给源站自己的域名；第三方播放域名一枚都不给）。
- 新增文案：`服务器不支持分段请求（AVPlayer 播不了这种流）：换 MPV 内核通常可播`
  ——真遇到服务端确实不支持 Range 的站，给的是能执行的下一步，不是「重试」。

## 2. 站内路径被当成「本地文件」（H動漫網 -17913 的根因）

日志原文：`[player] 播放失败：打开失败：... (-17913) ｜地址域名 ｜请求头 无`
——**地址域名是空的**，因为它是一条 `file://`。

  这些 id 现在走正常链路：先取剧集、再取地址（图源自己给的绝对地址 + 请求头）。
- 已用真站核过：H動漫網 的 m3u8（`bf.qugt.com:65`，直连/代理都通）能正常取到。

## 2. 巴卡漫画：卡片写着「可点【网页视图】」，按钮却不在

真机截图：首页超时那张卡上有「可点【网页视图】过校验（目标站：https://bakamh.com/）」，
但**只有「重试」**——因为按钮的判定只认「明确被 WAF 拦下」的特征串，超时不算。

现在把口径统一成一个函数 `webViewMayHelp`（`waf.dart`）：
- 明确被拦（NEED_WEBVIEW_VERIFY / cf-chl / 人机验证…）→ 给；
- **超时 / 网络失败 / HTTP 403 / 429 / 5xx → 也给**（CF 拦到超时、回 503 都常见，
  用户唯一的自救就是自己打开站点看一眼）；
- 需要外部桥接（reCAPTCHA v3）、纯脚本错误 → 不给（网页视图救不了）。
首页卡与探索页卡都用它决定「提示 + 按钮」——**两件事要么同时出现，要么同时不出现**。

## 3. 媒体地址的明文 http 一律升到 https（hanime1 这一类）

iOS 的 ATS 默认**拦掉 App 自己发出的明文加载**（只有网页视图内容放行，见 Info.plist
注释），而图源给的播放地址常写成 `http://`：地址本身能播，却被系统拦下 → 真机报
「播放链接中断」。图片管线早就统一升级（`upgradeToHttps`），视频这条链路没有。

现在 `SourcePlayback` 的条目地址、章节地址、逐线路地址都过同一个 `_secure`：
`http://` 域名升 `https://`，**IP 与 localhost 不动**（局域网/本地服务照旧）。

```dart
static Uri _secure(Uri uri) {
  if (uri.scheme != 'http') return uri;
  final host = uri.host;
  if (host.isEmpty) return uri;
  if (RegExp(r'^\d{1,3}(\.\d{1,3}){3}$').hasMatch(host) || host == 'localhost') {
    return uri;
  }
  return uri.replace(scheme: 'https');
}
```
