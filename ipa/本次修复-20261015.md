## 1. 源图标好多都没有

根因（2026-10-15 实测）：直接按 `${站点}/favicon.ico` 取图标这条路本身是错的——

| 站点 | `/favicon.ico` 实际返回 | 真图标位置 |
| --- | --- | --- |
| JComic | HTTP 200 + **HTML**（站点的 404 页） | 首页没有 `rel=icon`，暂时只能显示首字母 |
| 18禁漫 / NN韩漫 / 色友 / X漫 | 404 | 首页 `<link rel=icon>` |
| HANMAN18 | 404 | 首页 `/fav.png` |
| 巴卡漫画 | 403（Cloudflare） | 需要源站会话 |

新增 `lib/core/source/source_favicon.dart`，取图标顺序改为：
源脚本声明的 `icon` → `/favicon.ico` → `/favicon.png` → `/apple-touch-icon.png`
→ 全都不行才抓**首页**解析 `<link rel=icon>`（apple-touch-icon 优先、按 `sizes` 从大到小、跳过 SVG）。
并且：

- 请求走**全局网络队列**（与其它请求共用并发额度），带上该源**验证过的会话**
  （Cookie + 验证时的 UA）——但只发给源站自己的域名（`SourceRequestLog.ownsHost`）；
  一个候选都连不上时不再去抓首页，直接回退首字母，列表不跟着拖；
- 校验内容**真的是图片**（content-type + 字节魔数）：HTML 404 页、SVG、空响应都当「没有」；
- 按源缓存结果（含失败），列表滚动 / 切页签不再重复打同一个站。

本机 2026-10-15 直连实测：楠楠漫画 17203B、P5 9662B、MM-CG 318B、三四漫画 3241B、
X漫 5639B 都取到了真图标；18comic.vip / 漫蛙在本机网络下不通（NONE）。
`LumeSources._siteUrl` 现在也认 `HOSTS = ['https://…']` 这种写法（HANMAN18、K漫画
此前连站点地址都解析不出来）。

## 8. hanime1「播放链接中断」

**是反爬方向的限制，但和「网页验证没做完」不完全是一件事**：

- 该站普通 HTTP 请求会被 Cloudflare 拦（本机实测直连不通、走代理 403），
  播放地址是**独立播放域名**上的签名地址，按播放当时读取 —— 主站会话按纪律
  **不复制**给第三方播放域名（把主站凭据泄漏给第三方比拿不到画面更糟）。
- 本轮能做的两件事都做了：① 媒体请求会带上该源**验证过的 UA**，且当媒体就在
  **源站自己的域名**上时，会话 Cookie（`cf_clearance` 等）也会一起带上；
  ② 失败时日志新增一行「失败地址域名 + 本次带了哪些请求头」，下次再报可以直接
  看出是哪个域名在拒绝。重试按钮本来就会**重新向图源取一次地址**（签名地址过期
  的场景走这条）。
- 仍然需要：在手机 App 内完成该站网页验证后重试。桌面测试与代理环境都不能替代
  手机上的真实会话。

## 9. 北觅影视播放页 403

**这是站点按 IP 地区拦截，不是 App 或脚本能修的**：

- 本机 2026-10-15 实测：`v.luttt.com` **直连 200**、走境外代理出口返回 **567**
  （腾讯 EdgeOne 的拦截页，没有 JS 挑战可过）；同一集的 m3u8（`play.phimgood.com`）
  直连 200、走代理 **403**，带不带 Referer 都一样。
- 因此脚本把 403 与 567 一样按「站点按 IP 地区拦截」报错，明确提示「换直连或换该站
  可用的网络出口」，不再把用户引向网页验证窗（那两类拦截都没有挑战可过）。
- App 侧的 403 文案也补上了这一可能成因（此前只说「多半需要请求头或已防盗链」，
  会把用户带偏成反复重试）。
